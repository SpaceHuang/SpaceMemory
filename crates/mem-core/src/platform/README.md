# 平台层实现裁决

## Windows RDC 的用途与限制（2026-11-24）

### 背景

sidecar 会在后台把记录文件整理成搜索索引。查询只有在能证明索引覆盖了当前记录时才能使用它；否则必须直接读记录文件。

Windows `ReadDirectoryChangesW`（RDC）把目录变化异步交给 watcher。sidecar 发出的独立探测事件只能唤醒 watcher，不能证明更早的文件变化已经交付。因此，watcher 当时计数为零不等于“截至当前查询没有文件变化”。

### 选项与后果

1. **RDC 只触发后台维护，查询直读（已选）**：首次查询使用当前记录内容，不会因通知延迟返回旧索引；代价是 Windows 查询暂时失去索引加速。
2. **用 RDC 的零计数授权索引查询（不选）**：保留索引速度；若文件变化通知尚未交付，查询会把旧索引当成最新，等长且恢复修改时间的记录改写可能在首次查询中丢失。
3. **换用有查询时点覆盖边界的变更日志（未来方向）**：在证明来源有效的卷上可安全恢复索引查询；实现、权限要求和卷覆盖尚未验证，不能作为当前默认。

### 裁决、依据和护栏

- **日期与选择**：2026-11-24，维护者选择选项 1。
- **理由**：本仓库要求首次读取不能返回旧内容。暂时变慢可接受；返回错误内容不可接受。
- **依据强度**：微软文档说明 RDC 可异步完成，结果需要在该 I/O 完成后读取；本轮 Windows 实机时序尚未运行。静态边界足以否定“独立探测事件能证明 RDC 已完成”的假设。
- **可逆性**：以后若接入覆盖完整、权限条件明确且通过 Windows 时序验收的变更日志，可以恢复 indexed；当前数据格式和记录文件不变。
- **代码护栏**：`Subscription::can_prove_query_freshness` 对 RDC 返回 `false`；Hello 的 `undigested` 为 `null`；RDC 不向检查点发布器提供新鲜度证明。RDC 仍保留，用于驱动后台重建。
- **验证护栏**：Windows 测试需确认 sidecar 在场时 CLI/MCP 仍直读并返回等长改写后的新内容；另需覆盖 watcher 取消、等待 I/O 完成及 worker join。
- **未收口项**：调查 Windows 目标环境可用的强证明来源（包括所需权限、文件系统和网络卷覆盖）；来源不支持或覆盖缺口时继续直读。
