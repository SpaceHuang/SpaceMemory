## 分发形态（已裁决：混合模式，2026-11-05）

**源只有一份：本目录。** 构建/发布时由工具链自动衍生两种形态，任何一次 init 只消费一份：

1. **外部形态**：发布压缩包/安装器把本目录原样复制到 exe 旁（`builtin-types/`）——用户看得见、改得着，组织可替换；
2. **嵌入形态**：编译期 `include_bytes!` 打进二进制（携带点：`crates/mem-assets`）——保证裸 exe（含 `cargo install`）单独开荒不残废。

**`mem init` 查找顺序**：exe 旁 `builtin-types/`，或模板覆盖配置指定的目录（定名随格式规范 v1；git 的对应物是 `init.templateDir`）→ 命中用外部；未命中 → 用内嵌字节兜底。

**先例**：git 的 init 模板目录（随发行版安装 + `init.templateDir` 覆盖）；helix 的 `runtime/`（随包数据，绝不编译为逻辑）。

> **操作指南**：发布打包的具体步骤与实施注意见 [docs/rules/packaging.md](../../docs/rules/packaging.md)——分发配置时按需读取，本文件只记录裁决。

**未收口**（随格式规范 v1 定稿，设计文档开放问题40）：正式分发渠道承诺；模板覆盖配置定名；红线1"携带/认识"边界的规范条文。

## 红线1 裁决解释：禁"认识"，不禁字节级携带

- **违反红线1**：机制代码里出现类型字段结构（Rust 结构体）或类型专用逻辑——R8.2 零知识被破坏，R8.1 声明式引入失效；
- **不违反**：字节级打包且从不 parse/校验/解释——机制对类型内容仍零知识，就像压缩包搬运文件；
- **试金石**：改任一类型的字段定义，只应改动本目录的数据文件，不得要求改动任何 Rust 代码；
- **护栏**：`crates/mem-assets` 是唯一携带点，对外契约仅 `assets() -> [(相对路径, 字节)]`，零依赖；仓库其他代码不得引用这些字节的内容。

## 规则

- **自举检验（红线13）**：principal 与 view 必须经类型声明引入——本目录即其声明来源；`mem init` 建店时播种并自举首条 principal（D9）；
- **本目录是播种资产，不是运行时事实源**：`mem init` 将两件套复制进数据目录 `types/`，数据目录中的副本才是运行时唯一事实源，用户可直接修改（R2）；店开起来之后，本目录与运行时再无关系；
- 新增内容类型 = 新增两件套，基础设施零改动（R8.1）。
