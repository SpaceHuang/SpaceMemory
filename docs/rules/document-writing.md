# 文档写作指南

> **定位**：写/改三类交付文档时读——需求（含基线修订）、技术方案与规范、执行计划。
> **篇内路由**：评审友善度（对一切交人评审的文档生效的底线）→ §0–§1；写规范/技术方案 → §2；排执行计划 → §3；改需求 → §4；交付前自检 → §5。
> **一句话**：文档的合格判据是"读者照着能做出唯一行为"；对交人评审的文档再加一条——**评审人只读评审层即可裁决，并且知道自己在批什么**。

## 0. 前提：评审是质量保障的一部分，不是仪式

本项目的质量模型：机器可判定的规则由机制强制（设计文档红线），判断型取舍由人裁决（评审）。因此**评审参与度 = 质量保障的覆盖面**：文档写得只有作者能读，评审就无法真正发生——实际发生的是裁决权静默移交给作者，评审退化为签字仪式，且这个失效没人会报告。

反推出四条硬性结构要求（不是文风建议）：

1. **评审层自足**：评审人只读决策条目与证据摘要即可裁决——不翻代码、不翻其他文档、不追问作者。判定句：**把评审层单独摘出，交给三天后没跟进的自己，疑问数 = 0**。
2. **评审范围显式**：每轮评审附**待批准清单**——本轮批什么、明确不批什么。不在清单上的内容不构成已批准。
3. **评审火力聚焦**：作者**自曝三处**——自己认为最可能被推翻的三个点，每处写"什么证据会推翻它"。
4. **阐述自说明**：论证的每一步只依赖本文已给出的内容与读者常识，**不能假设读者一边对照其他文档或代码、一边审阅**。交叉引用与锚点只承担核验与下钻，不承担首次理解。三条写法：
   - **就地最小解释**：概念首次在论证中使用时，就地给一句"它是什么、为什么在这里需要"；完整定义仍在真源处。这与"单一真源"不冲突——真源管"规则是什么"，就地解释管"读者此刻需要知道什么才能跟上"；复制的是规则全文，解释的是理解所需的最小语义；
   - **引用不承重**：删掉全部锚点与链接后，论证仍完整可读。反例："沿用 D12 的状态三元组进行回填"——读者必须另开设计文档才能跟上。正例："沿用状态三元组（记录的位置 ∈ records/attic/absent、版本、全文摘要；下钻：D12）进行回填"；
   - **打印测试**：把文档打印出来（或关掉其他一切文件）从头只读这一份——**哪里需要"先去翻另一份才能跟上"，哪里就是缺口；修法是就地补最小解释，不是加长引用清单**。

## 1. 决策条目（评审层的最小单元）

每条需要人拍板的条目——决策、开放问题、规范默认值、对红线的任何变更——按六要素写：

| 要素 | 要求 |
|---|---|
| ① 背景 | 这件事是什么、影响什么 |
| ② 选项 | 至少两个，含"维持现状" |
| ③ 后果 | 每个选项**写"破坏了会怎么表现"**，不写机制词 |
| ④ 可逆性 | 选错了能不能改回来、代价是什么 |
| ⑤ 依据强度 | 哪些已验证、哪些没数据 |
| ⑥ 推荐 + 默认 | 推荐哪个；人不决定时默认怎么走 |

范例（本仓库已达标）：`assets/builtin-types/README.md` 的混合分发裁决——六要素齐全，未收口项显式。

- **翻译纪律**：条目正文用表现语言（如"同一次删除会被登记两次"）；本仓库锚点体系（R#/D#/红线#/开放问题#）是给执行者的索引，**不进决策条目正文**，只出现在行末"下钻"。
- **禁用通道**：数据格式、接口、默认值、对外行为不得以"建议值 / 推荐默认 / 视情况"身份通过——它们是裁决条目，必须人批。

## 2. 写规范 / 技术方案

- **承诺配对**：强断言（原子 / 永不 / 必被检出 / 按字节保持）必须同处给出机制 + 验证点；给不出 = 机制没想清 = 删断言或降级措辞。
- **数字可对账**：正文报的每个数（字段数、关键字数、预算值、上限值）都能在机层（schema / 代码 / 测试）数出同样多。
- **新增面清单**：相对既有设计新增的交付面（新类型、新字段、新接口、新配置）逐条列出并注明来源条款；来源不是已裁决的决策项 → 先补决策再写方案（防加戏）。
- **排除方案要写**：选了什么、为什么排除另一个（一句话即可）。
- **迁移与回退**：任何格式变更写清迁移算法、完成标记语义、回退实体；"幂等创建"不算迁移。

## 3. 排执行计划

- **单向真源**：验收与不变量的真源在方案/规范，计划只引用锚点、不新造验收。分界判据：**这段内容会不会需要在不改方案的前提下被重写？会 → 它属于计划**。方案内不出现复选框，计划内不重定义验收。
- **任务粒度三判据**（同时成立才合适）：能独立验收；依赖只指向已完成的编号；范围单一（一个任务只接通一条链路或一个契约）。
- **门禁二分**：本机可执行的（自动化测试、本地构建、可复现命令）才能当开发前置门禁；依赖外部环境的（如本机 Windows、验证 macOS/FSEvents 行为）一律列为**外部验收项**——开工前显式列出，不阻塞开发。判定句：**当前机器上执行不了的门禁不是门禁，是外部验收项**。
- **前置只引用更早的证据**：每项门禁证据标注产出任务编号；编号晚于门禁位置即违规。
- **状态标记**：`- [ ]` 未开始 / `- [～]` 进行中（全角，防渲染为删除线）/ `- [x]` 完成（**产物 + 验证证据齐备**；"代码已改"或"测试通过"单独不构成关闭）。
- **回退演练排在启用之前**，且被启用任务显式引用。

## 4. 改需求

- **开放决策表四列**：决策点（含至少两个选项）/ 现状与派生差异 / 必须在哪个节点前关闭 / 关闭条件。禁止"或 / 建议 / 视情况"糊在正文。
- **指标三要素**：可观测事件 + 分母 + 阈值；"显著 / 足够 / 常数级"不算指标。
- **范围三清单**：本期做（按价值排序）/ 明确不做（写不做的后果）/ 未来再引入；非目标不得抵消目标。
- 判定句：**同一句话，能否做出两种都合规的实现？能 = 没写完**。

## 5. 交付前自检

1. 每条决策条目六要素齐全，单独摘出可裁决（疑问数 = 0）。
2. 待批准清单 + 自曝三处已附。
3. 强断言全部承诺配对（机制 + 验证点）。
4. 正文数字全部可在机层对账。
5. 未验证项显式列出（影响 + 谁拍板）。
6. 无一条格式 / 接口 / 默认值以"建议"身份混过。
7. 决策条目正文无裸锚点（锚点只在下钻）。
8. 计划不重定义验收；方案 / 规范内无复选框。
9. 打印测试通过：论证自说明、引用不承重——关掉其他文档只读这一份，每个论证步骤都能跟上。
