## 结论与范围

**方案层通过：首轮两项 P1 阻断已关闭，未发现新的安全阻断；保留一项非阻断的执行顺序澄清。**

可按修订稿开展默认关闭的 FSEvents 维护提示实现。这里通过的范围是“后台维护提示、查询继续直读”的技术方案，不包括批准实现合并、默认启用、发布或关闭开放问题39。修订稿规定的真实 Mac 验收与回退演练仍须取得证据，才能满足其合入及默认启用条件。

本轮并未证明 FSEvents 可以支持严格的新鲜性同步。关闭 B1 的原因是修订稿撤除了该依赖：即使通知延迟，客户端仍直接读取记录，后台索引落后不再导致查询返回旧答案。

## Q1：步骤4的验收范围应排除步骤5才产出的回退证据

**级别：P2，非阻断文档澄清。**

**位置：** 修订稿第165行（§7外部验收6）、第176–178行（§8步骤4–6）。

步骤4要求执行“第7节全部 macOS 项”，但其中第6项要求完成下一节的回退演练；该演练排在步骤5。按§8“按以下顺序实施”逐项关闭任务，步骤4会需要后一步证据。整体验收与默认启用的安全边界仍明确，因此本项不重新打开安全阻断，也不妨碍步骤1–3的开发。

**建议修订：** 将步骤4的范围明确为“第7节 macOS 外部验收1–5项”；步骤5对应外部验收6；步骤6继续同时引用步骤4与5的证据。也可将回退要求移入整体完成条件，保持任务依赖只指向更早步骤。

**关闭条件：** 每一步能够仅凭本步及更早步骤的证据独立关闭，同时保持回退演练先于默认启用。依据：`docs/rules/document-writing.md` §3的依赖顺序要求。

## 自曝三处

1. **范围收缩的价值取舍。** 本轮认可的是安全可实施性；查询仍直读，因而没有交付 macOS查询加速。若批准目标仍是立即获得索引快路径，本方案不能满足该目标，需要独立方案，不能据本次通过扩大范围。
2. **方案与实现边界。** 信号账务、根身份核验及隔离接线只有文档要求，未取得运行证据。后续若实现仍把提示计数送入freshness，应重新阻断，不得援引本报告放行。
3. **顺序澄清的严重度。** 本轮将Q1视为可在执行前明确的小范围文档修正；若执行系统必须逐步硬关闭全部证据，需先修该引用再推进步骤4，但无须阻塞步骤1–3。
