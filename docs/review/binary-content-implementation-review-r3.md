## H1（高优）：非文本正文预览描述符超 BD3 的 128 字节上界——正文 ≥1MB 时 `mem show` 在 debug 构建 panic

**位置**：

- `crates/mem-core/src/body.rs:85-95`：`non_text_descriptor`——模板固定部分约 124 字节＋字节数的十进制位数＋正文摘要前缀 8＋记录 ID 36，总长随位数增长；`debug_assert!(d.len() <= 128)` 在 debug 构建生效；
- `crates/mem/src/commands/mod.rs:897`：CLI `cmd_show` 的唯一调用点。`--body` 缺省为 true（`cli.rs:78`），即**钻取默认形态**就会进入描述符分支。

**缺陷机制（表现语言）**：正文字节数达到 7 位十进制（≥1,048,576 字节，即 ≥1MB 的图片）时描述符 131 字节，超过 BD3 承诺的"总长上界 128 字节"3 字节；debug 构建下该越界命中 `debug_assert` → `mem show <图记录id>` 直接 panic 崩溃（退出码 101）。MCP `mem_show` 不生成描述符（非文本正文 `body=null`），不受影响。现有测试的最大非文本正文样本为 256 字节——描述符恰 127 字节压线通过，上界对大正文不成立这一事实未被测试暴露。

**生产复现（已确认）**：临时店写入 1MB PNG 样本（1048576 字节）；`mem show <id>`（不带任何可选参数）→ `thread 'main' panicked at crates\mem-core\src\body.rs:93: 描述符模板上界 128 字节（BD3）：131`，exit=101。同一记录在 release 形态不崩溃，描述符 131 字节（超承诺、无功能损害）。

**影响评估**：题库配图 ≥1MB 常见；开发、验收、评审流程惯用 debug 构建（r1/r2 评审即用 `target/debug/mem.exe`）。崩溃面覆盖"五个读命令全部可用"承诺的最常用命令（show 默认形态），且不挑选记录是否损坏——比验收 6 的损坏语境更宽。BD3 的承诺配对（机制＋验证点）恰好漏掉大正文分支。

**关闭条件**：

1. 模板对字节数限位（如 ≥1MB 用工程计数法/缩写），使上界对任意 `usize` 成立；`debug_assert` 保留；
2. 新增大正文样本回归：≥1MB 与 ≥1GB 两档（位数 7 与 10），断言描述符长度 ≤128 且 debug 构建不 panic；CLI e2e 补一条 1MB 非文本记录 `show` 默认形态跑通。

## H2（高优）：`path_is_inside` 对无目录部分的相对路径漏判——cwd 在店内时 BD1 的店内拒绝被绕过（两个消费点同破）

**位置**：

- `crates/mem-core/src/paths.rs:155-172`：目标路径 `parent()` 为空串（即无目录部分的相对路径，如 `x.png`）时直接返回 false（"不在店内"）；
- 消费点一：`crates/mem/src/commands/mod.rs` `write_body_out`（`--body-out` 目标店内拒绝，BD1）；
- 消费点二：`crates/mem-core/src/ops.rs` `resolve_restore_source`（`restore-body --source file:` 的店外约束）。

**缺陷机制（表现语言）**：相对路径 `x.png` 判"不在店内"放行后，落盘原语按进程当前目录解析——用户把工作目录切进店内（`cd` 进店看文件后顺手执行命令）再 `--body-out x.png`，文件就落在店根，成为信封管辖外的旁挂文件：迁移复制目录会带走它、git 状态显示 untracked、信封校验不覆盖。这正是 BD1"目标位于店目录内 → 响亮拒绝（防止经读通道在店内产生信封管辖外的旁挂文件）"要防的形态。`file:` 源同函数同破：店内相对路径被接受为恢复来源。

**生产复现（已确认，两个消费点）**：

1. cwd=店根：`mem show <id> --store . --body-out smuggled.png` → 成功返回 body_out 元信息，`smuggled.png`（1MB）出现在店根；
2. 同 cwd：`restore-body <id> --store . --expect <令牌> --source file:inside-backup.md`（店内相对路径备份）→ 接受并执行（版本 +1）。

**影响评估**：无覆盖、无既有数据损坏（B2 修复的原子独占创建仍保证不覆盖既有文件）；危害是店内产生脱离管辖的旁挂文件与"店外来源"约束失效。触发形态自然（店内相对路径），无需蓄意。

**关闭条件**：

1. 判定前将双方绝对化（店根 canonicalize、目标以当前目录补全）再做比较；
2. 回归：cwd 在店内时 `--body-out x.png` 拒绝且店内无新文件；`file:x.md`（店内相对路径）拒绝。

## L1（低优）：同一函数的误拒方向——词法前缀无分隔符边界、相对店根下 `./x`、`../x` 全被误判店内

**位置**：`crates/mem-core/src/paths.rs:159-161`（词法前缀分支）；`crates/mem-core/src/store.rs:179`（`Store::open` 不绝对化店根，`--store .` 时店根就是 `"."`）。

**缺陷机制（表现语言）**：两个误拒形态，方向都是"宁严勿松"（不会产生旁挂文件，只是合法店外导出被拒）：

1. 店根是目标路径的字符串前缀：店 `./store`、目标 `./store-backup/out.png` → 误判店内 → 拒绝。备份目录命名（如 `~/.agent-memory-backup`）撞上店根 `~/.agent-memory` 即触发；
2. 店根为相对路径（`--store .`）时，词法分支拿 `"."` 当前缀，任何以 `.` 开头的相对目标（`../out.png`、`./out.png`）都被误判店内 → 拒绝。

**生产复现（已确认）**：形态 1 `--body-out ./store-backup/out.png` → "目标位于店目录内"误拒（目标实为兄弟目录）；形态 2 cwd=店根、`--body-out ../tok-skip.png` → 同样误拒（目标实为店外上级目录）。

**关闭条件**：与 H2 同一修复（双方绝对化＋分隔符边界感知的前缀比较），一并回归。

## L2（低优）：`file_bytes_at` 以 stderr 英文文本判定"路径不在该版本"——git 消息本地化环境下误判

**位置**：`crates/mem-git/src/process.rs`（`BodyHistory::file_bytes_at`，`stderr.contains("does not exist")` 分支）。

**缺陷机制（表现语言）**：git 经 gettext 本地化消息；非英文 locale 的 git 把"路径不存在"输出为本地化文本 → 匹配失败 → 误入 Err 分支。后果：`history` 锚定扫描逐版本取文件时，遇到"该版本无此文件"（合法跳过分支，如删除后重建的路径历史）会中断整个恢复并给出误导成因。显式 `git:`/`file:` 源与英文环境不受影响。

**关闭条件**：以退出码语义或先行的存在性探测（`git cat-file -e <rev>:<path>`）判定，不依赖消息文本；补一条非英文成因说明或探测式判定的单测。

## 观察项（登记备查，不要求动作）

1. **`commit_batch` 无条件把 `.gitattributes` 入批**（有 .git 时）：`ensure_for_write` 与提交之间的毫秒窗口内该文件被外部删除的话，`git commit -- <path>` 的 pathspec 语义会把删除入树。自愈路径完整：下轮受管写补种并入批恢复、verify 审计在窗口内如实报告"未入提交树"。无需动作。
2. **MCP `body_b64` 每页独立 base64**（页长非 3 的倍数时含 padding）：宿主必须逐页解码后按字节拼接，不能把各页 base64 文本首尾拼接（e2e 测试演示的是正确用法）。建议后续在工具描述补一句明确该用法，防宿主侧踩坑。
