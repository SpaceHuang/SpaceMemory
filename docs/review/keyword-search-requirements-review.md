## 阻断项

### B1 R10.2/R10.8 检索域匹配谓词未钉死到唯一实现，决策③④⑥与自曝 2/5 的"现状"依据失实

- **载荷域（键名不参与是既有裁决，R10 未体现）**：代码事实——两执行器共用的命中谓词对 payload **逐值**匹配（递归含数组/对象值），**键名不参与**：`crates/mem-core/src/search.rs:16-27`（注释明言"键名不参与——键名查询两模式都必须不命中，r8 裁决"）、`crates/mem-index/src/sqlite.rs:348`（indexed 侧同语义）。而本文：
  - R10.2 只写"载荷"域，未说值还是含键名；
  - 决策③后果(a) 以"载荷的键名等结构性文本可能被查询误命中（如查询 value 命中所有含该字段名的记录）"论证代价——该形态在现状中**不存在**；
  - 自曝 2 前提"载荷键名参与子串匹配"、自曝 5 推演"否定一个常现键名（如 type）会排除几乎全库"、决策⑥依据"第二词项过滤全域匹配的键名误命中"——全部建立在"键名参与匹配"这一与 r8 裁决相反的假设上。
  - **判定句失败**：按"载荷域含键名"实现 = 静默扩大命中面（对外行为变更，未经裁决登记）；按"仅值"实现 = 自曝 2/5 所述风险不存在、相关论证落空。两种实现都合规 = 需求没写完；R10.3 完备召回的"命中集合"在键名含查询串时无定义，验收 2"不含查询串的记录不出现"不可判定。
- **身份域（现状是前缀匹配，不是子串）**：`search.rs:40` `fold(id).starts_with(q_fold)`——身份域为**前缀**语义（direct/indexed 同源）。R10.8 写"各词项折叠后于**任一域作为连续子串**出现"：按字面实现即把身份域从前缀扩为子串（如查询 "xyz" 命中 id "abc-xyz"），属对外行为变更，未在范围三清单或自曝中登记；按现状保留前缀又与 R10.8 字面冲突。决策④依据"已验证——命令行前端现状为子串语义"对身份域不成立（其余三域确为子串/逐值子串）。
- **处置建议**：
  1. R10.2 逐域钉死谓词：载荷域 = **值域（含嵌套值），键名不参与**（追认 r8 裁决与现状，自曝 2/5 与决策③⑥相关句子随之改写或删除）；
  2. 身份域谓词（前缀追认 vs 子串扩张）是**新的微裁决点**——按 document-writing §1 六要素补一条决策条目，或并入决策④裁决记录补注；若裁子串，须在"明确不做/行为变更登记"处显式登记；
  3. 验收 2 补身份域构造（如以 id 前缀为查询词的命中/不命中对）。

### B2 正文域无条件参与检索，与 R11 已裁决④(b) 正面冲突，且本文零承载联动

- **冲突**：R10.2"检索域覆盖……全部四个域——身份、别名、载荷、正文"、R10.3"凡满足查询匹配条件……的记录必须全部可达"均为无条件条款；而 `binary-content-requirements.md` v0.2 决策④(b) **已裁决**（2026-11-07）："正文区不是合法 UTF-8 的记录，其正文区不参与关键词检索（身份、别名、结构头字段照常参与）"。正文恰含查询串编码巧合的非 UTF-8 记录：按 R10.2/R10.3 必须命中，按 R11 ④(b) 必须不命中。两案均"已裁决、待并入基线"，任一先后按现状并入即把矛盾写进评审标尺。
- **现状佐证**：当前实现为有损解码后匹配（`search.rs:49` `String::from_utf8_lossy(body)`）——这正是 R11 ④(a) 已否决的伪命中形态，R11 ④(b) 落地时必然改动该行为；R10 并入若不带例外子句，两条需求将同时约束同一行为且互斥。
- **联动缺失**：R11 侧已挂账（其 §7.2 登记"R10 并入基线时检索域措辞同步收口"，见 binary-content-requirements-review.md r2 第 3 条），本文 §1.3"与既有需求的关系"、§7 登记动作、范围三清单对 R11 **零提及**——收口义务只在单侧，并入时两侧可能同时"以为对方管"。
- **处置建议**：R10.2/R10.3 正文域补例外子句（"正文区非合法 UTF-8 的记录，其正文区不参与——见 R11"），§7 增加与 R11 的联动登记行；顺带统一称法（R11"结构头字段" ↔ 本文"载荷"，即 R11 评审 L1 挂账）。

### B3 R10.1"本期的落地缺口：关键词检索与载荷字段过滤"与代码事实不符

- **代码事实**：CLI 实装 23 个子命令（`crates/mem/src/cli.rs:28-207`，dispatch 穷尽匹配全部可达）；MCP 共 14 工具（`crates/mem-mcp/src/tools.rs`）。除 find 外，实装且 MCP 无对应的还有：**merge**（记录合并/去重，`commands/mod.rs:1065`→`ops::merge`）、**bind**（默认视图绑定，`commands/mod.rs:1144`）、**view**、**agenda/apply/fix**（维护例程，`commands/mod.rs:1163-1219`）；init 已被本文"初始化引导等运维动作的豁免边界归设计"预告，其余各项无此豁免预告。
- **影响**：(a) R10.1 自定的最低对等清单为"五项基础读能力 + **完整写路径**"——merge 属写路径，即按本文自己的清单，当前对等缺口不止两项；(b) 该断言以事实身份位于已裁决分项内，随基线并入即固化错误现状陈述——与 R11 评审 B2 同型失效（错误断言以"已验证"面貌进入标尺）；(c) 决策②依据"MCP 现有 14 个工具恰好五项缺一"本身为真，但紧邻的"本期落地缺口仅两项"会误导读者将其外推为对等缺口的完备清单。
- **处置建议**：R10.1 改为如实分级陈述——读能力五项缺一（find，真）；写路径已知缺口 merge；bind/view/agenda/apply/fix/init 归"运维与工具面盘点（设计阶段）"显式列名而非笼统豁免。对等原则裁决本身不受影响，纯文本修正。

## 高优项

- **现象**：R10.6 断言"不存在'已知可能漏掉刚发生写入'的检索路径"——按 document-writing §2 承诺配对（强断言同处配验证点），验证面只落在验收 3"手改某记录正文"（**外部改**）。“外部**增**"（手放新文件入 records/ 即可命中——若实现只复核索引已知行、不发现索引外新文件，验收 3 照样通过而 R10.6 被违反）与“外部**删**"（已删记录不得残留命中）无构造。验收 2 亦未构造身份域命中（与 B1 联动）。
- **处置建议**：验收 3 扩为改/增/删三态构造；验收 2 补身份域。

### H2 "状态层全部记录"的记录范围未钉死

- **现象**：需求陈述"在状态层全部记录中定位"——"记录"按基线状态三元组含 attic（tombstone）与 absent。现状 find 只扫 records/（`ops.rs:60-62` `scan_all` 枚举 records/）。扫 attic 与不扫 attic 两种实现都合规（判定句失败）；R10.3"必须全部可达"字面甚至可读出"attic 记录经检索可达"。
- **处置建议**：一句话钉死，建议"检索域为 records/ 现存记录；attic 不参与，经 restore 回 records/ 后可检索"。
