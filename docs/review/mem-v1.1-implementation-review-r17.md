## B17-1 [P1 / Critical] 对生成的记录目标和锁目标同样执行目录边界约束

**位置**：

- add：`crates/mem-core/src/ops.rs:384-399`。
- delete 目标：`crates/mem-core/src/ops.rs:700-709`。
- restore 目标与记录锁：`crates/mem-core/src/ops.rs:756-773`。
- 锁文件打开与覆写：`crates/mem-core/src/lock.rs:190-204,217-238`，`crates/mem-core/src/platform/macos.rs:49-50`。

### 已确认修复的部分

本轮通过现存记录路径的 canonicalize 校验，以及 fix 对 BadArgument 的直接传播，封住了 R16 的原始入口：

```text
fix records/../../outside.md：退出 1，店外字节不变，未产生店外锁文件
show records/escape/outside.md：退出 1，记录路径越出店目录
fix records/escape/outside.md：退出 1，记录路径越出店目录
```

扫描也已跳过子目录/文件符号链接，新增的 ID/别名读取回归通过。这些关闭证据保留，不将原反例误报成仍可复现。

### 残留一：写入目的地没有经过同一校验

校验目前集中在 `get` 和 `fix_record`。add 自己推导 records 路径，delete 推导 attic 路径，restore 推导 records 路径；这些目标在取锁、创建目录、发布记录或改名之前没有调用相同的边界检查。

以下均用本轮真实 `target/debug/mem`、全新临时店与空的店外目录复现；符号链接预先存在，不需要竞态或并发换链。

| 操作 | 预先设置 | 实际结果 |
|---|---|---|
| add memory | `records/memory` 是指向店外空目录的链接 | 退出 0、`created=true`，店外出现完整记录及 `.md.lock` |
| delete memory | 活记录正常在店内；`attic/memory` 链接到店外空目录 | 退出 0，记录从 records 被移到店外，返回店内 tombstone 路径 |
| restore memory | tombstone 正常在店内；空的 `records/memory` 被替换为店外目录链接 | 退出 0，tombstone 被移到店外，返回店内 records 路径；店外还产生锁文件 |

最小 add 场景：在新店建立 `records/memory -> 店外目录`，随后执行：

```sh
mem --store "$STORE" add memory --payload '{"title":"outside-created"}'
```

真实返回及后续观测：

```text
exit=0
created=true
rel=records/memory/<ID>.md
店外出现 <ID>.md 和 <ID>.md.lock
mem show <ID>：退出 1，记录不存在
```

delete、restore 同样在成功后无法按 ID 找回。原因是新的扫描安全规则跳过链接，而写入者仍跟随链接发布；这使“写入成功”与“能从店中读回”直接矛盾。删除/恢复原件也已离开所选店目录，复制店目录无法包含这些记录。

### 残留二：合法记录路径不能保证它的锁文件也在店内

即使记录本身在正常目录中，`<record>.md.lock` 仍可单独链接到店外文件。记录路径的 canonicalize 校验不会检查这条锁文件路径；平台打开跟随链接，随后的 owner JSON 覆写会修改链接目标。

真实 CLI 复现：

1. 正常 add 一条店内 memory，取得 ID、相对路径及令牌。
2. 将该记录的 `.md.lock` 替换成符号链接，目标为店外普通文本，原字节为 `valuable unrelated bytes`。
3. 按 ID 和有效令牌正常 update 该记录。

```text
update：退出 0，version=2
店外普通文件变成 {"pid":...,"host":"unknown","ts":...}
```

这一分支不要求店外文件是合法记录；被覆盖的是与记录无关的普通文件。它不是上一轮已经修好的 fcntl 生命周期问题，而是锁资源路径本身没有守住存储边界。

### 修复方向与关闭条件

将边界约束放到所有实际文件落点的共同路径，而不只放在读取解析入口：生成的记录目标、移动目的地、记录锁等都必须受约束；在写锁元数据、mkdir、create 或 rename 之前确认合法。锁文件的打开方式也必须避免跟随越界链接。merge 等共用移动目标的调用方一并审计，避免逐前端补丁。

本项至少需要以下接口级回归：

1. add 遇到 records 子目录外链：明确拒绝，店外不出现记录或锁文件，不追加创建事件。
2. delete 遇到 attic 子目录外链：明确拒绝，原 records 字节保留，店外与事件日志不变。
3. restore 遇到 records 子目录外链：明确拒绝，原 attic 字节保留，店外与事件日志不变。
4. 正常记录的 `.lock` 外链：明确拒绝，店外任意普通文件不被 owner JSON 覆盖，记录和事件也不修改。
5. 合法店内目录下的 add/delete/restore/update、损坏记录 fix 继续正常工作。

本轮实证限于静态、已存在的符号链接；无需以并发换链攻击为前提才能成立。Windows 的 junction/重解析点对应边界应列入平台验证，不能仅由 macOS 结果推定。
