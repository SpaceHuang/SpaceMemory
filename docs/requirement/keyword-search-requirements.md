## 1. 问题定义

### 1.1 缺口定位

按"执行体读取状态层"的基本动作盘点，五项基础读能力在两个前端上的现状（2026-11-07 代码核验）：

| 基础读能力 | 命令行前端 | 最高集成档前端（MCP） |
|---|---|---|
| ① 建立工作视图（摘要） | ✓ brief | ✓ mem_brief |
| ② 清单与按类型过滤 | ✓ list（支持类型参数） | ✓ mem_list（支持 type 参数） |
| ③ 关键词检索 | ✓ find | **✗ 缺失** |
| ④ 单条钻取 | ✓ show | ✓ mem_show |
| ⑤ 增量获知 | ✓ diff | ✓ mem_diff |

缺口的成因不是遗漏，而是**没有任何需求条目约束"一个前端的能力完备性"**：最高集成档（宿主仅通过结构化工具协议访问状态层、无命令行与文件系统直接访问的形态；下钻：基线 R8 能力分档）缺了检索一项，现有的补救是降级路径——宿主断连或能力不足时改用命令行前端。降级路径的既有语义是**故障兜底**；当检索必须日常性地走另一前端时，命令行实际成了最高集成档的**常规构成**，这与能力分档的设计意图相悖：一个只有工具协议、没有命令行的宿主（沙箱执行体、远程受控环境）将整体失去按内容定位的能力。

### 1.2 起源场景中缺口的表现

教材库评测表中与本文相关的两行：

1. **"关键词全文（'绝对值'）→ ⚠️ MCP 前端无 find 工具，系统性检索以 CLI 为主"**——本文的主体：把关键词检索确立为需求，使最高集成档自足。
2. **"按类型只看法则/公式 → ⚠️ find 兜底或导出 JSONL 后处理"**——经核验部分成立：按**类型**过滤两端均已可用；真正缺的是**载荷字段级**过滤（如按内容字段里的"法则/公式"标记筛）。该项经评审（2026-11-07）**纳入本期**（R10.10），不再是缺口。

### 1.3 与既有需求的关系

- **分层访问**（基线 R4.1"摘要/清单 → 条件过滤 → 定位单条 → 钻取全文"）：检索是"条件过滤"层中**按内容过滤**的具体化。该层的既有实现按信封字段过滤（类型等）；按内容过滤是同一层的另一个入口，不是新层。
- **确定性机制**（基线 R7 的强制类）：字符串是否出现完全可机械判定。若不由基础设施提供，每个宿主只能自行遍历文件，预算、截断、新鲜性语义各自实现一遍——恰好复制了应予机械保证的部分。检索归强制类，不归约定教学。
- **检索精度与库规模**（基线判断 3"小到中等规模下结构化摘要即索引达标；不强制语义检索"）：本提案位于两者之间——关键词子串检索是廉价的确定性机制，不触发判断 3 的升级条件，也不与"语义检索非目标"冲突（见范围三清单）。
- **降级路径**（基线 R8.9）：继续成立，继续服务故障与连通性异常。本提案收紧的只有一点：降级不得成为常规操作路径（该收紧本身是决策②的裁决对象）。
- **结构零知识与跨类型通用操作**（基线 R8.2/R8.4 的既有立场：通用操作只依赖信封、不依赖载荷字段）：载荷字段过滤看似与之冲突；相容解法是**声明驱动**——类型声明指明本类型哪些字段可过滤及取值形态，基础设施只实现"按声明解释并执行"的通用机制，不内嵌任何具体类型的字段语义。基线并入时须对 R8.4 字面补注记（见 §7）。
- **二进制正文**（R11——同目录在途草案 `binary-content-requirements.md`，其决策④(b) 已裁决）：正文区非合法 UTF-8 的记录，其正文区不参与关键词检索（身份、别名、载荷照常参与）。本文 R10.2 的正文域例外子句与该裁决同向、互为例外挂账——R11 侧已登记"R10 并入时检索域措辞同步收口"，本文 §7 第 6 条补齐对侧。现状实现为有损解码后匹配，正是 R11 已否决的伪命中形态，由 R11 ④(b) 落地时收口，本文不新增冲突。称法注记：本文"载荷"即 R11 部分条目所称"结构头字段"，统一随 R11 评审 L1 挂账执行。

## 2. 需求陈述（R10 拟）

**陈述**：执行体能以一个关键词查询为条件，在状态层**当前存活的记录**中定位"内容满足该查询"的记录——存活＝records/ 现存层；受管墓碑（删除后暂存于 attic/ 等待恢复的记录）与已消失记录不参与检索与过滤，经恢复接口回到 records/ 后恢复参与。查询由一个或多个空白分隔的词项构成（词项间组合语义见 R10.8，否定词项见 R10.9）。清单与检索结果可按类型声明声明的载荷字段值过滤（R10.10）。两个前端功能对等（R10.1）；该能力在其所属集成档内自足可用，其行为是确定性的、有预算的、新鲜的。

**动机**：用户记得的往往是内容片段（一个术语、一句规则、一个页码），不是它存在于哪个类型、哪条记录——按内容定位无法由"按已知结构过滤"替代。没有该能力时唯一兜底是全量导出后人工翻找，成本随库规模线性增长，正是基线 R4 要消除的形态。

**分项**：

- **R10.1 前端功能对等**（2026-11-07 用户立为原则）：命令行前端具备的每一项工具与功能，工具协议前端均须对应具备；新增能力须同批落两端。两个前端只是指令入口形态不同（人敲命令 vs 执行体调工具），不构成功能支持差异。降级路径继续存在，但仅服务故障与连通性异常，不得成为常规操作路径。最低对等清单为五项基础读能力（①摘要视图 ②清单与类型过滤 ③关键词检索 ④单条钻取 ⑤增量获知）加完整写路径。对等缺口如实分级（2026-11-07 r1 评审核验：命令行 23 子命令 vs 工具协议 14 工具）——**读路径**：缺口为关键词检索（本提案落地）；**写路径**：已知缺口为 merge（记录合并，属本条的"完整写路径"最低清单，其映射实施登记入工具面定稿排期，不在本提案范围）；**运维与工具盘点**（设计阶段逐项裁决映射或豁免，不笼统豁免）：bind（默认视图绑定）、agenda/apply/fix（维护例程）、init（初始化引导）。注记（r2 评审 H4）：view 为**视图执行**（读路径，按 id 取视图定义跑过滤并分页），工具协议前端 mem_list 已带 view 参数同语义覆盖——两端均已可用，**非对等缺口**，不移入盘点清单。本提案不断言对等缺口"仅"读路径一项。载荷字段过滤（R10.10）是本提案新增能力，按本条原则同批落两端。
- **R10.2 全域匹配（谓词逐域钉死，不留两可）**：检索域覆盖记录承载内容的全部四个域，各域命中谓词如下（对现状的逐域追认，两执行器共用的命中谓词单源为证）：
  - **身份域**：前缀——查询词折叠后作为记录身份键的**开头**出现即命中（前缀 vs 子串已经决策⑧裁决为前缀）；
  - **别名域**：连续子串；
  - **载荷域**：**逐值**连续子串——查询词折叠后在载荷的每个字符串值（含数组与嵌套对象中的叶子值）**内部**作为连续子串出现，即该值命中；**键名不参与匹配**（既有裁决的追认：查字段名不命中，查字段值命中）；
  - **正文域**：连续子串，且以正文字节**是合法 UTF-8** 为参与前提——正文区非合法 UTF-8 的记录，其正文区不参与匹配，其余三域照常（与 R11 决策④(b) 的已裁决例外一致，双侧挂账、并入基线时同步收口；现状实现为有损解码后匹配，属 R11 已否决形态，由 R11 ④(b) 落地时收口）。
- **R10.3 完备召回**：凡满足查询匹配条件（R10.2/R10.8/R10.9）的**存活记录**必须全部可达（经分页续读穷尽，不重复）；命中集合与"对真相层现存记录逐条执行同一匹配"的结果一致——记录域为 records/ 现存层（attic/ 与已消失记录不参与，恢复后恢复参与），正文域以合法 UTF-8 字节为参与前提（R10.2 的例外子句同此适用）。索引等加速结构只允许影响速度，不允许改变命中集合。
- **R10.4 折叠等价**：检索不因大小写与等价字符形式漏检（"Abs"与"abs"互可检出）；折叠规则单源，与身份键路径推导所用一致。
- **R10.5 预算与确定性分页**：清单、检索命中、过滤结果等**一切读结果形态**一律分页——单次返回规模有确定上限，超限必须显式标注并给出续读方式，命中总量不得转化为调用方单次的上下文消耗（基线 R4.2 的读路径应用；2026-11-07 用户重申）。分页顺序确定——同一库同一查询两次检索（其间无写），命中序列完全一致。
- **R10.6 新鲜即时**：检索反映此刻真相层状态——记录被外部修改后，不执行任何维护动作即可被检索命中；不存在"已知可能漏掉刚发生写入"的检索路径。
- **R10.7 定位与钻取分离**：检索返回命中清单（定位信息与钻取入口，含身份与并发令牌），不携带全文；全文经单条钻取获得（基线 R4.1 分层的既有语义）。
- **R10.8 多词与**：查询可由空白分隔的多个词项构成；记录须包含全部肯定词项（各词项按 R10.2 的逐域谓词命中——身份域前缀、其余域连续子串）且不包含任何否定词项（R10.9）方为命中。仅含一个肯定词项的查询，命中语义与既有单串检索一致。分词器不因此引入——每个词项仍按逐域谓词匹配，不引入词元概念。
- **R10.9 否定词项**：词项可携带否定标记（标记的语法形式归设计阶段），其匹配串按 R10.2 的逐域谓词在全部域均不命中时该否定词项满足。带否定词项的查询须至少含一个肯定词项；纯否定查询不构成有效检索，须被明确拒收——拒收须为显式错误响应，不得表现为空命中清单或全库清单。否定词项不改变完备召回：命中集合仍与"对真相层现存记录逐条执行同一匹配"一致（R10.3）。
- **R10.10 载荷字段过滤**（2026-11-07 用户裁决纳入本期）：清单与检索结果可按载荷中声明的字段值过滤（起源场景如"知识板块=几何""条目形态=法则"）。过滤由**类型声明驱动**：类型声明指明本类型哪些字段可过滤及取值形态；基础设施只实现"按声明解释并执行"的通用机制，对具体类型零知识（与基线 R8.2/R8.4 相容）。过滤可与关键词查询组合（词项与 + 字段条件同时生效）；过滤结果同等受 R10.5 预算分页约束，命中定义与 R10.3 的记录域与匹配前提一致。类型声明变更后，既有记录的过滤服务降级标注、不拒绝服务（基线 R8.7 的应用）。

**责任边界**：本需求保证**确定性检出**——"字符串存在则可检出"。不承诺相关度排序（最相关的排最前）、不承诺意图理解（同义、翻译、语义扩展）。检索质量属于判断型行为，归类型约定与执行体（基线判断 2 的既有划分）。

**验收**：

1. 仅具备完整工具协议档的宿主（无命令行、无文件系统访问），完成"关键词 → 命中清单 → 钻取单条 → 依载荷溯源（如教材页码）"全链路，全程不触发降级路径；
2. 在身份/别名/载荷/正文分别构造含查询词的记录：身份域用"id 前缀＝查询词、内容域不含该词"的记录（命中）与"id 中段含查询词、内容域不含该词"的记录（不命中——决策⑧裁决为前缀）；载荷域另构造"键名含查询词、值不含"的记录（不命中——键名不参与）；检索可经续读穷尽全部命中且无重复；不含查询词的记录不出现；
3. 外部增/改/删三态，均不做任何维护动作、直接检索：外部新放入一条含查询词的记录文件——即命中（覆盖"发现索引外新文件"）；外部手改某存活记录正文加入查询词——即命中；外部删除一条命中记录（受管删除进 attic 与不经接口直接删文件两种各构造一次）——即不再命中且无残留；
4. 命中数超预算时响应显式标注并给出续读方式，按续读可读完剩余命中；
5. 同一库同一查询连续两次检索（其间无写），命中序列完全一致；
6. 构造仅含词项 A、仅含词项 B、同时含 A 与 B、均不含的记录各若干，以空白分隔查询"A B"检索，仅"同时含 A 与 B"的记录命中，且可经续读穷尽；
7. 构造"含 A 含 B""含 A 不含 B""不含 A"的记录各若干，以否定词项查询"A NOT B"检索，仅"含 A 不含 B"的记录命中且可经续读穷尽；纯否定查询被明确拒收——拒收须为显式错误响应，不得表现为空命中清单或全库清单；
8. 按类型声明声明的载荷字段过滤清单与检索结果，仅返回匹配记录且可经续读穷尽；与关键词词项组合时两者同时生效；
9. 前端对等抽验：命令行前端的每项读取能力在工具协议前端均有对应入口（本期核验面为检索与过滤；全量盘点随工具面定稿收口）。

## 3. 范围划界

**本期做**（按价值排序）：

1. 完整工具协议前端（MCP）补关键词检索工具，语义满足 R10.2–R10.9（R10.1 是对等原则，由本条与第 4 条共同承载落地），与命令行前端的检索行为一致（命名与参数形状归设计阶段）；
2. 多词与与否定词项：空白分隔多词项（含否定词项）的服务端裁定（R10.8/R10.9）；
3. 载荷字段过滤：清单与检索结果按类型声明声明的字段值过滤，可与关键词组合（R10.10，2026-11-07 用户裁决纳入）；
4. 命令行前端同批升级：多词与/否定词项解析、载荷字段过滤参数在命令行侧同批落地（R10.1 对等原则的落实——防"只改工具协议前端"的读法）；
5. 跨前端一致性验收：同一查询（含其解析语义与过滤条件）、同一库，两个前端的结果集合与顺序一致（机制上如何保证——单源实现或一致性测试对账——归设计）。

**明确不做**（写不做的后果）：

1. **相关度排序**——后果：命中按稳定元数据序呈现，检索精度依赖查询词本身，大量命中时需多翻页；
2. **布尔扩展**（或、裸排除、括号分组）与**短语精确语法**（引号）——后果："或"由客户端对各词项分别检索后并集承担（传输量≈答案量，服务端仅省常数因子的重叠去重）；裸排除（查询仅含否定词项）的命中集≈全库枚举，作为检索算子退化，由 R10.9 明确拒收；含空白的短语精确匹配不再直接可用（决策⑥后果），起源场景（中文词项、短语内空格罕见）受影响有限；与位排除已纳入本期（决策⑦），不再列于本条；
3. **语义检索**——继承基线范围划界，非目标。注明非目标不抵消目标：关键词检索是确定性机制，语义检索是规模驱动下的未来升级，两者不互斥（基线判断 3）。

**未来再引入**：

- 载荷字段过滤的深化（跨字段条件、值域语法——基础的单字段过滤已入本期，其余随类型声明词汇表演进）；
- 检索的类型/域限定参数；
- 相关度排序与布尔扩展（或、括号分组、短语引号语法）；
- 规模驱动的高级检索（基线判断 3 的升级路径）。

### 决策② 需求形状：档内自足 vs 点状修补

- **依据强度**：已验证——MCP 前端现有 14 个工具恰好五项缺一（其余四项齐备），选项 (a) 在现状上只强制一件事、不产生额外即期改动；未验证——未来前端形态。

### 决策③ 检索域：全域 vs 受限域

- **背景**：记录内容分布在四个域（身份、别名、载荷、正文），检索扫哪些域决定"找得到什么"。
- **选项**：(a) 全域——四域任一命中即命中；(b) 受限域——仅正文与身份/别名，载荷不参与。
- **后果**：(a) 破坏了会怎么表现——载荷的**值**参与检索后，短查询词会在长值上产生部分子串命中（与正文域同型，非结构性新增）；字段键名不参与匹配（既有裁决），"找有哪些字段"这类结构发现场景检索不服务。(b) 破坏了会怎么表现——载荷值承载的信息（起源场景中的页码、板块、年级等字段值）检索不到；查询无结果时用户无法区分"没有这条记录"与"记录在但搜不到"。
- **可逆性**：(b)→(a) 扩域不触及存量；(a)→(b) 收缩会悄然改变命令行前端的既有检索行为，属对外行为变更，须重新评审。
- **依据强度**：已验证——命令行前端现状即全域，且载荷域为**逐值**匹配、键名不参与（命中谓词单源，r8 裁决），身份域为前缀（独立成决策⑧）、别名/正文为子串——本条是对现状的追认而非扩张；未验证——值域部分子串误命中的实际频率（无数据）。
- **推荐 + 默认**：(a)。默认 (a)；值域误命中若实测成为问题，走"域限定检索"（未来项）而非收缩全域。
- **裁决记录**：2026-11-07 用户裁决选项 (a)——载荷一并检索（值域）。
- 下钻：`crates/mem-core/src/search.rs::record_matches`（命中谓词单源：身份前缀、别名子串、载荷逐值且键名不参与、正文有损解码子串——末项由 R11 ④(b) 落地收口）。

### 决策④ 匹配语义：连续子串完备召回 vs 分词检索

- **背景**："命中"的定义决定正确性验收的形态。子串语义：查询串作为连续字串出现即命中；分词语义：按词元匹配，依赖分词器。
- **选项**：(a) 连续子串完备召回（折叠等价下）；(b) 分词/词元检索。
- **后果**：(a) 破坏了会怎么表现——无索引加速时性能上限为线性扫描，超大规模下退化可见（加速失效的场景由正确性兜底语义覆盖：慢但不漏）。(b) 破坏了会怎么表现——跨词边界的查询静默漏检（中文尤甚：查询"对值"命中不了分词为"绝对/值"的记录），且引入分词器这一额外语料依赖；漏检是静默的，用户无法区分"没有"与"没搜到"，正确性验收也无法机械判定。
- **可逆性**：二者不可叠加共存（叠加即回到"哪种语义是裁定者"的问题）；任一方向切换都须全量重验检索行为。
- **依据强度**：已验证——别名/载荷值/正文三域现状即连续子串语义（身份域为前缀，独立成决策⑧），中文起源场景实测可用；未验证——超大规模下的性能上限（无数据，性能基线在设计侧另立）。
- **推荐 + 默认**：(a)。默认 (a)。
- **裁决记录**：2026-11-07 用户裁决选项 (a)——连续子串。
- 下钻：设计文档开放问题29（性能基线）。

### 决策⑤ 本期排除项

- **背景**：检索周边有四个相邻能力（载荷结构化过滤、相关度排序、布尔扩展、语义检索），各有真实声索；纳入与否决定本期范围与节奏。其中"多词与"单独成决策⑥，本条裁决其余部分。
- **选项**：(a) 全部排除，列入明确不做与未来清单；(b) 至少纳入载荷结构化过滤（起源场景表格的第二个未决项）。
- **后果**：(a) 破坏了会怎么表现——"按字段只看某类内容"继续走组合路径（多步操作），起源场景表格第二行维持未直接命中。(b) 破坏了会怎么表现——过滤形状依赖各类型声明的字段设计，而类型集仍在增长；提前定形容易把第一个场景的字段形状铸成通用机制，后续类型被迫迁就。
- **可逆性**：(a)→(b) 未来引入属增量；(b)→(a) 撤回已发布的过滤语义属对外行为变更。
- **依据强度**：已验证——类型声明词汇表已含主题类注记钩子，未来结构化过滤有既定挂点；未验证——各场景字段过滤的真实使用频率（无数据）。
- **推荐 + 默认**：(a)。默认 (a)。
- **裁决记录**：2026-11-07 用户裁决：载荷结构化字段过滤**纳入本期**（推荐 (a) 未被采纳——起源场景存在真实声索，落于 R10.10）；相关度排序、布尔扩展（或/括号/短语语法）、语义检索维持排除。新增未收口项——可过滤字段在类型声明中的表达词汇（如何声明"哪些字段可过滤、取值形态"）归设计阶段，与既有自定义关键字同批评审。
- 下钻：设计文档 D19（类型声明词汇表与主题注记）。

### 决策⑥ 多词与：本期纳入 vs 维持单串

- **背景**：真实检索常带两个独立约束（起源场景如"八年级"+"方程"）。多词约束可由客户端对每词分别检索后求交，也可由服务端一次裁定；两者的成本结构不同。
- **选项**：(a) 本期纳入"空白分隔多词项、全部包含方命中"（R10.8）；(b) 维持现状单串语义，多词与留在未来清单；(c) 本期纳入完整布尔语法（与/或/非/括号/引号）。
- **后果**：(a) 破坏了会怎么表现——命令行前端含空白的既有查询从"短语精确匹配"变为"词项与"，命中集扩大为原语义的超集：不产生漏检，但词项散落各域命中的记录会进入清单，依赖短语精确性的既有用法需适应。(b) 破坏了会怎么表现——命中集悬殊时客户端求交不可行（如词项 A 命中上万、词项 B 命中五条，须先传完 A 的全部命中才能相交，预算通道承受无意义传输），两词约束场景退化为低效遍历。(c) 破坏了会怎么表现——完整布尔的"非"须分两态裁决：裸排除（查询仅"NOT X"）的命中集≈全库枚举，作为检索算子退化——清单分页+客户端过滤同价，服务端无增益；与位排除（"A AND NOT B"）虽可判定且不破完备召回，但客户端组合的浪费上界为正词项命中数、服务端收益二阶（对比正向"与"的无界剪刀差）。再叠加语法、优先级与转义规则把查询语言复杂度提前带进需求，超出起源场景的已证需求。
- **可逆性**：(a)→(b) 收回词项语义属对外行为变更，须重新评审；(a)→(c) 属增量扩展；(c)→(a) 撤回已发布语法代价大。
- **依据强度**：已验证——词项与语义可机械判定（每词项按其所属域谓词逐记录可测）；附带收益可推演——第二词项过滤任一域的部分子串误命中（短查询在长值/长正文上的部分命中，见自曝 2）；客户端求交的传输成本为推演，无本库实测数据；未验证——起源库中多词查询的实际占比（无数据）。
- **推荐 + 默认**：(a)。默认 (a)；短语精确与或/裸排除留在范围三清单的排除项与未来项（§3）。
- **裁决记录**：2026-11-07 用户裁决选项 (a) 纳入——用户以否定词项查询需求（决策⑦）确认多词结构，该查询语义以 R10.8 为前提。
- 下钻：R10.3/R10.8；决策④（子串语义按词项适用，不引入分词器）。

### 决策⑦ 与位排除：本期纳入 vs 留未来项

- **背景**："A 但不含 B"类查询（起源场景如"方程但不含八年级"）在多词结构上只差否定词项一一种法；机制与多词与同构（逐记录判定），但服务端收益量级不同（二阶 vs 无界）。
- **选项**：(a) 本期纳入否定词项（肯定词项 ≥1，R10.9）；(b) 留未来项（v0.3 的处置）。
- **后果**：(a) 破坏了会怎么表现——查询面多一种语法成分（否定标记），解析与跨前端一致性验收面随之变宽；客户端方案的浪费（传完正词项全量命中再差集）被消除，但该浪费上界为正词项命中数，属二阶收益。(b) 破坏了会怎么表现——用户已声索的真实查询（2026-11-07）在预算通道下退化为低效差集或不可行，场景诉求落空。
- **可逆性**：(a)→(b) 收回否定语义属对外行为变更，须重新评审；(b)→(a) 即本次路径，机制与多词与同构、增量有限。
- **依据强度**：已验证——逐记录可判定性（与多词与同构）、用户声索（2026-11-07 裁决）；未验证——否定词项在起源库的实际使用频率（无数据，本裁决依据为用户判断而非统计数据）。
- **推荐 + 默认**：(a)（用户已裁决）。
- **裁决记录**：2026-11-07 用户裁决纳入本期。未收口项——否定标记的具体语法形式（前缀写法、大小写约定、是否需转义）归设计阶段工具面定稿。
- 下钻：R10.9；决策⑥（同构性与收益对比）。

### 决策⑧ 身份域谓词：前缀（追认现状） vs 子串

- **背景**：r1 评审（B1）核验：身份域现状为**前缀**匹配——查询词折叠后作为身份键的开头出现即命中；本文 v0.5 曾笼统写"任一域连续子串"，按字面实现会把身份域静默扩为子串（查询"xyz"命中身份"abc-xyz"），属未登记的对外行为变更。谓词逐域钉死后（R10.2），这是唯一遗留的拍板点。
- **选项**：(a) 前缀——追认现状；(b) 子串——身份域与其余三域统一。
- **后果**：(a) 破坏了会怎么表现——只记得身份中段片段时（如身份"quadratic-equation/…"中的"equation"）身份域搜不到，须靠别名/载荷/正文的内容域子串兜底（身份是地址不是内容，中段记忆本就宜走内容域）。(b) 破坏了会怎么表现——身份中段碎片大量误命中结构相似的身份（路径共享中段的记录族），命中清单被地址噪音挤占；身份从"地址"滑向"内容"，与内容域语义混淆；且属对外行为变更（现状为前缀），须在范围划界显式登记。
- **可逆性**：(a)→(b) 与 (b)→(a) 均属检索行为变更，须重新评审；现状即 (a)，维持零迁移成本。
- **依据强度**：已验证——现状为前缀（两执行器共用命中谓词，代码核验）；未验证——中段片段检索的实际使用频率（无数据；内容域子串已覆盖其兜底）。
- **推荐 + 默认**：(a)。默认 (a)——身份是地址不是内容。
- **裁决记录**：2026-11-07 裁决选项 (a) 前缀（追认现状）——随 r2 评审有条件通过确认（评审独立核验推荐与代码事实一致：两执行器共用谓词即前缀）；并入文本不携带"待裁决/按默认执行"措辞（r2 评审 L5）。
- 下钻：R10.2 身份域谓词行；`search.rs::record_matches`。

## 6. 自曝——最可能被推翻的点

1. **R10.1"档内自足"可能被判过强**：本仓库当前部署形态是 MCP 与命令行并存，"检索降级命令行"在日常中被当作正常用法——R10.1 把这种用法判为非常规路径。*什么证据会推翻*：用户确认"双前端并存即目标形态、降级可作检索的常规依赖"，届时 R10.1 退化为决策②(b) 的点状修补。（**裁决后状态**：2026-11-07 用户确认对等原则并加强之，本条关闭——残留风险转为"对等盘点的豁免边界"，归工具面定稿。）
2. **载荷值域的部分子串误命中（r1 评审改写——原"键名噪音"前提失实）**：键名不参与匹配（既有裁决，已追认为 R10.2 谓词），残留风险是短查询词在长值上的部分命中（如查询"八"以部分形态命中"八年级"值）。*什么证据会推翻*：起源库实测中值域部分命中污染清单且域限定（未来项）无法缓解。另记一处语义边界：字段键名不可检索——"找哪些记录有某字段"属结构发现，检索不服务该场景。
3. **决策④完备召回的性能上限**：目标规模（万级记录）下直读精筛路径的耗时无实测。*什么证据会推翻*：性能基线实测显示目标规模下不可接受，且规模升级路径被否决——届时须在"保持完备、性能另筹"与"放宽为近似召回"之间重新裁决（本文推荐前者，静默漏检不可接受）。
4. **决策⑥的既有行为变化**：命令行前端含空白的查询从短语匹配变为词项与——若既有用户依赖空格短语精确检索（英文内容场景），此变化构成实质干扰。*什么证据会推翻*：存在依赖空格短语语义的既有查询用法，且散落词项的超集命中在实践中污染结果、域限定等未来项又无法缓解。
5. **否定词项与全域匹配的交互（决策⑦；r1 评审改写——键名前提失实）**：否定词项按各域谓词匹配（值域不含键名）——否定一个高频值片段（如"年级"）会排除几乎所有含该值的记录。语义正确但可能不合直觉。*什么证据会推翻*：实际使用中此类误用频繁且域限定（未来项）无法及时缓解，届时需求层须裁决"否定词项限定匹配域"或强提示约定。
6. **载荷字段过滤的声明词汇是新设计面（决策⑤裁决后转移的风险）**：当初排除过滤的理由是"过滤形状依赖各类型声明的字段设计，提前定形易铸死"；纳入本期后，该风险转移为类型声明词汇表的扩展设计（声明哪些字段可过滤、取值形态），若设计不当会把第一个场景的字段形状铸进基础设施。*什么证据会推翻*：词汇表设计评审中发现第二个类型无法自然表达其过滤需求，或基础设施为实现过滤开始内嵌类型字段语义。
