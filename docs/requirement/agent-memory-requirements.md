## 1. 问题定义

### 1.1 背景

以 LLM 为核心的 Agent 正在被用于持续性、跨会话的真实工作：跟随一个项目演进、记住用户的偏好与纠正、管理跨越数天的任务。Agent 的角色正在从"一次性问答工具"转变为"长期参与工作的角色"。

长期角色需要记忆。而当前 Agent 的构造与环境，存在四对未解决的基本矛盾：

1. **执行体易逝 vs 工作连续。** 上下文窗口随会话结束而清空，进程随任务结束而终止；但用户的工作——项目、偏好、教训、未尽事项——是连续的。没有外部状态，每个会话都从零开始，用户反复教、Agent 反复丢。
2. **注意力有限 vs 知识累积。** 执行体可承载的上下文是稀缺资源；它需要记住的东西却随工作持续累积。"记得越多"若意味着"每次取用越贵"，记忆系统会反转为负资产。
3. **工具更迭 vs 资产沉淀。** 用户使用的 Agent 工具持续更替。状态若散落在各工具内部（格式各异、互不相通），换工具即碎片化作废。Agent 的记忆本质上是**用户资产**，不是任何工具的附属品。
4. **单体假设 vs 多方协作。** 现实中多个 Agent、多个进程、以及人本身，会并发地读写同一份工作状态。"同一时刻只有一个写入者"的假设在协作场景必然导致更新丢失与状态损坏。

### 1.2 状态的时间谱系

需要外部化的状态在时间尺度上跨越三个量级：

| 尺度 | 典型内容 | 寿命 |
|---|---|---|
| 会话级 | 进行中的任务、执行进度、下一步计划 | 小时～天 |
| 项目级 | 用户偏好、历史教训、项目事实、外部系统指针 | 周～月 |
| 永久级 | 结构化知识、参考资料、沉淀的方法论 | 长期 |

三者性质各异，但共享同一批底层要求：持久、可共享、访问有预算、可信可维护。因此本需求要求的是**一个统一的状态层**覆盖全谱系，而不是按时间尺度分别建设互不相通的设施。

### 1.3 一句话表述

> 为 Agent 建设一个外置的**第二记忆**：持久的、用户自有的、多方可共享的、访问有预算的、可信可验证的、对错误写入者健壮的、强制与教学分工明确的、能以最低门槛覆盖一切宿主的。

## 2. 需求总览

| 编号 | 需求 | 一句话 |
|---|---|---|
| R1 | 状态连续性 | 执行体的边界不是状态的边界 |
| R2 | 状态主权 | 状态是用户资产：开放格式、可审计、无锁定 |
| R3 | 并发一致性 | 多写入者并发是默认场景，不是异常 |
| R4 | 上下文经济 | 状态增长不得推高单次访问成本，预算机械强制 |
| R5 | 可信可验证 | 不承诺永不出错，承诺错误可发现、可治愈 |
| R6 | 写入者健壮性 | 坏写入是常态输入：可识别、可隔离、可修复 |
| R7 | 强制与教学分离 | 机器可判定的归基础设施，需要判断力的归约定 |
| R8 | 通用与渐进增强 | 异构结构声明式扩展（统一信封 + 类型声明）；最低能力宿主可完整闭环 |
| R9 | 层级与提炼 | 实例→规则→原则的派生结构可表达、可追溯、可收敛、可维护 |
| R10 | 关键词检索与前端对等 | 按内容确定性定位；两前端功能对等，新增能力同批落两端 |
| R11 | 二进制内容承载 | 图等二进制以受管记录承载：字节保真、关联确定、取回对等、检索不受染、损坏可治愈 |

## 3. 需求详述

### R1 状态连续性

**陈述**：工作状态必须独立于任何单次执行体存续。任何新启动的执行体——新会话、新进程、乃至不同的工具——都能获得截至当前时刻一致的状态视图。

**动机**：这是 Agent 从"一次性问答"升级为"长期协作"的前提。短期的任务进度和长期的知识积累是同一条需求在不同时间常数上的表现，应统一覆盖。

**分项**：
- R1.1 会话级状态（进行中的任务与进度）跨会话存续，可被任何执行体接手；
- R1.2 项目级与永久级状态（偏好、教训、事实、指针）跨会话、跨工具存续；
- R1.3 存在稳定的读取入口：执行体无需任何人工转述或事先历史，即可自主建立完整的工作视图。

**验收**：执行体 A 在状态层写入工作现场后终止；新启动的执行体 B（允许是不同工具）仅通过状态层即可恢复 A 的全部工作现场并继续工作。

### R2 状态主权与可携性

**陈述**：状态是用户资产。以开放格式存储，人类可直接阅读、理解、编辑；不绑定任何厂商或工具；用户可随时脱离全部工具，独立完成审计、修改、迁移与备份。

**动机**：锁在工具内部的记忆既不可迁移也不可审计：换工具即归零，用户也无法回答"它到底记了我什么"。人类可读提供双重价值——**审计**（建立信任）与**兜底**（工具失效时人手仍可修复）。

**分项**：
- R2.1 存储格式有公开规范，无需专有软件即可读写；
- R2.2 非专业用户借助操作系统自带能力（文本查看/编辑工具）即可浏览和修改全部状态；内容为二进制的记录降格为"可审计＋经接口替换"——结构信息可读，内容字节经接口或人手整文件替换修改（唯一明文例外，见 R11 责任边界）；
- R2.3 迁移成本约等于复制一个目录；卸载所有工具后数据完整保留、语义不损；
- R2.4 绕过工具接口的人手修改是合法输入（与 R3.5 衔接）。

**验收**：停用一切 Agent 工具后，用户用文本编辑器即可读懂自己的全部状态并修改文本类状态（二进制记录按 R2.2 例外处理）；将存储位置整体复制到另一台机器，一切照常工作。

### R3 多方共享与并发一致性

**陈述**：状态层必须把"多个写入者并发操作"作为默认场景：写入者集合开放（多 Agent、多进程、人直接编辑）。一致性按写入路径分界承接：**受管写入**（经受管接口或遵循写入协议）以强制保证承接（R3.1–R3.3）；不经接口的人手/外部直写无法被状态层拦截过程，以"事后如实可见与可治愈"承接（R3.5、R6），不承诺其中间态不可见或更新不丢失。

**动机**："共享"是状态升级为团队与组织记忆的前提；而写入者多于一个时，并发就是常态。状态层必须给出明确的冲突语义，而不是指望写入者互相错开。

**分项**：
- R3.1 写原子性：经受管接口（或遵循写入协议）的单次写要么完整生效、要么完全不生效，不存在可被读到的中间态；外部直写的原子性不由状态层强制，其可能产生的中间态按 R3.5 在下次访问时如实可见；
- R3.2 更新不静默丢失：对同一记录**经受管接口**的并发读-改-写，或者串行化、或者显式报告冲突并让后写者感知先写者的成果。外部直写不做事前拦截：人手（如保存旧缓冲区）或外部工具覆盖受管写入（或反向）造成的丢失不是静默丢失——结果在下次访问时按 R3.5 如实可见，并由 R6 的识别与修复通道承接；
- R3.3 创建唯一性：**经受管接口**的创建中，同一逻辑身份不会被并发创建出两份（唯一性由基础设施强制，不依赖写入者"先查后建"）；不经接口的人手复制/新建导致的重复不承诺事前阻止，由基础设施在后续访问时发现、告警并按 R6 隔离；
- R3.4 引用完整性：记录间的引用不因删除或并发而悬空——阻止、级联清理或显式报告，语义必须确定；
- R3.5 外部修改收敛：不经接口的人手或外部修改，必须在下一次访问时如实可见，不得被任何缓存旧值覆盖。

**验收**：经受管接口的多进程并发写入竞态测试中，无静默丢失、无重复创建、无悬空引用；不经接口的外部直写场景中，不承诺拦截中间态与覆盖丢失，但下一次读取立即如实反映外部修改（R3.5），由此产生的重复与损坏被识别、告警并可经接口修复（R6）。

### R4 上下文经济

**陈述**：状态总量的增长不得转化为执行体单次访问的注意力成本增长。访问必须分层，且单次访问的规模上限由基础设施机械强制。

**动机**：执行体的注意力是最稀缺资源，且其对自身消耗没有可靠自律。预算若是提示词层面的期望，必然被击穿；必须是机制层面的上限。

**分项**：
- R4.1 分层访问：摘要/清单 → 条件过滤 → 定位单条 → 钻取全文，各层均可独立到达，允许只取所需；
- R4.2 硬预算：每次访问的返回规模有确定上限；超限必须截断并**显式标注**（含继续读取的方式），不得静默丢弃；
- R4.3 增量刷新：执行体能以远低于全量的成本获知"自上次查看以来发生了什么变化"；
- R4.4 预算的执行者是基础设施，与写入者的自律无关。

**验收**：状态总量增长一个数量级，常规操作（建立工作视图、定位并读取单条）的返回规模保持常数上界；所有截断均有标注与续读路径。

### R5 可信与可验证

**陈述**：状态层承载的是"写入时为真"的信息，而世界持续变化。本需求不是"记忆永不出错"（不可达成），而是**错误可发现、可治愈**。

**动机**：语义上的过时与矛盾无法机械消除。可行的目标是让坏状态——陈旧、重复、矛盾——可见、廉价可发现、可按协议治愈，并把"记忆中的真"与"此刻的真"明确区分。

**分项**：
- R5.1 新鲜度可见：每条记录携带何时写入/最近修改的时间信息，且在摘要层即可见；
- R5.2 存疑策略：使用方可依据时间信息设置怀疑规则（如：超过 N 时间的项目类信息默认需要验证）；
- R5.3 依赖前验证：约定要求执行体在依据记忆行动前验证现状，状态层不承诺"记着的就是现在的"；
- R5.4 矛盾收敛：同一事实的新认知应引导更新既有记录而非新增记录；唯一性等机制应主动促成收敛；
- R5.5 维护例程：重复/陈旧/矛盾的清理是显式的、有预算的、经确认后执行的例程，而非不可审计的后台自动改写。

**验收**：给定一条已被现实推翻的记录，遵循约定的执行体能在有限步骤内发现它、修正或删除它，并留下可追溯的变更。

### R6 对不完美写入者的健壮性

**陈述**：写入者包括概率性出错的数据主体（LLM）和会手误的人。坏写入是**常态输入**，状态层必须相应设计。

**动机**：把"写入者永远正确"当前提的系统，会被第一次坏写入击穿：要么局部错误放大为整体不可用，要么坏数据永久滞留无人能修。

**分项**：
- R6.1 可识别：不合规写入能被识别，并明确报告是哪一条、为何不合规；
- R6.2 可隔离：局部坏数据不得使整体不可用——读路径跳过坏条目、附告警、继续服务，绝不崩溃；
- R6.3 可修复：每条坏数据都存在**经由接口**的修复路径；同时不禁止人手修复，两条修复路径都通。

**验收**：向存储中注入若干格式损坏的条目后，全部读取路径正常工作并附告警；这些条目随后可完全经由写入接口修复至合规。

### R7 强制与教学的分离

**陈述**：状态管理的规则分两类，交付载体必须分开：

- **(a) 机器可判定规则**——唯一性、原子性、引用完整性、预算上限等。由基础设施在**受管写入路径**上无条件强制；不经受管路径的外部直写不可事前拦截，但必须可发现、可收敛（R3.5/R6）；
- **(b) 判断型行为**——什么值得记、何时召回、如何组织表达。以**约定/协议**形式教学交付，可版本化、因领域而异。

**动机**：提示词纪律是可靠性最低的保证层，模型发挥的波动直接转化为数据损坏；而判断型行为需要持续演化、因域而异，铸死在基础设施里会僵化。分不清一条规则属于哪一类，就会把该强制的写进提示词、把该教的焊进代码——这是状态层设计中最重要的一条架构约束。

**分项**：
- R7.1 每条具体规则都能被显式归类为 (a) 或 (b)；
- R7.2 禁止把 (a) 类规则降级为约定——凡可机械判定的，必须在**受管写入路径**上无条件强制；不经受管路径的外部直写无法被事前强制，但必须可发现、可收敛（R3.5/R6），机制不得以"外部写入者会遵守协议"为前提；
- R7.3 禁止把 (b) 类行为铸死进基础设施——约定与机制解耦，独立演化；
- R7.4 约定有单一事实源，并能按宿主能力多级下发（见 R8）。

**验收**：规则清单评审中，不存在既未强制也未教学的规则；对每条 (a) 类规则，构造一个恶意或出错的写入场景，基础设施仍能守住不变量。

### R8 通用性与渐进增强

**陈述**：

- **扩展性（异构结构）**：不同场景需要不同的记录结构——任务要状态机字段，决策记录要结论/依据/备选项，记忆要主题分类。基础设施对"记录长什么样"零知识；每种内容类型以**声明**（结构定义 + 约定文档）描述自身，引入新类型零代码；所有记录共享统一信封，结构差异只存在于载荷之内。
- **渐进增强**：状态层的核心价值锚定在数据本身。宿主集成能力分档（完整工具协议 → 行为教学 → 约定注入 → 原始数据访问），逐档叠加增强，**任一高档缺失都不破坏闭环**；最低档必须能完成完整的读写与维护。

**动机**：记忆的价值随覆盖面超线性增长——只在单个工具里可用的记忆是碎片，碎片化的记忆等价于没有记忆，因此低门槛与宽兼容是硬需求而非优化项。在结构异构上存在两个等价失败的极端：**单一万能结构**（所有类型共用超集字段或自由键值——校验失效、过滤失义、记录退化为浆糊）与**每类型硬编码**（基础设施认识每种类型——每个新场景都要改代码，基础设施成为变更瓶颈）。可行域只剩中间形态：**统一信封 + 声明式类型定义**，本需求将其约束为硬性质。同时宿主生态异质且持续变动，价值锚在数据上，才不与任何单一宿主能力共存亡。

**分项——扩展性与结构异构**：
- R8.1 声明式引入：新内容类型的引入是配置与文档工作，基础设施零改动；
- R8.2 结构零知识：基础设施不内嵌任何内容类型的字段结构，记录结构完全由该类型的声明提供；
- R8.3 统一信封：所有记录共享基础设施拥有并管理的最小信封——身份、类型标识、时间元数据、并发版本、引用能力；
- R8.4 载荷隔离：类型特有字段与自由正文属于载荷，仅由类型声明解释；跨类型通用操作（列清单、过滤、排序、预算控制、级联清理）只依赖信封，不依赖任何载荷字段（注记：R10.10 的载荷字段过滤由类型声明驱动、按声明解释执行，属通用机制对声明的依赖，不构成对具体类型载荷结构的内嵌依赖。）；
- R8.5 校验强制：每个类型的结构声明同时是可执行的校验定义（字段类型、必填性、取值域、引用目标存在性），由基础设施机械执行，不依赖写入者自律；
- R8.6 校验分档：校验强度是类型声明的属性——判定型结构（如任务）坏字段即坏记录，拒收并提供接口修复通道（R6.3）；模糊型结构（如记忆）容忍未知字段，降级服务并告警；
- R8.7 演化容忍：类型声明变更后，既有记录仍可读——降级、标注、不拒绝服务；历史数据的迁移是显式例程（R5.5），不做隐式自动改写；
- R8.8 两件套交付：每个类型同源交付"校验定义 + 约定文档"，分别承载 R7 的 (a)/(b) 两类规则。

**分项——渐进增强**：
- R8.9 降级路径：各宿主能力档之间存在明确、文档化的降级路径；
- R8.10 最低档闭环：最低能力档（能够到达数据本身）足以完成一次完整的状态写入与读回；
- R8.11 单一副本：不同宿主、不同会话访问的是**同一份**状态，不产生平行副本。

**验收**：
- 新增一种内容类型的过程不触碰基础设施代码；
- 两个结构完全不同的类型共存于同一状态层，跨类型通用操作（清单、过滤、排序、预算、级联）不感知载荷差异；
- 对严格校验的类型，不合结构的写入被拒且可经接口修复；对宽松校验的类型，未知字段被容忍并附告警；
- 类型声明变更后，按旧声明写入的记录仍可读（降级 + 标注），且存在显式迁移路径；
- 仅具备最低数据访问能力的环境中，一次完整的写入-读回-清理流程可完成。

### R9 层级、派生与提炼

**陈述**：知识在抽象层级上形成结构：具体实例（一次纠正、一个事件）之上沉淀出个别规则，个别规则之上提炼出一般原则。状态层自身不做提炼（判断 2：提炼是需要判断力的行为），但必须使调用方执行体的提炼工作**可表达、可追溯、可收敛、可维护**。

**动机**：没有层级支持的记忆是平面的——每条记录彼此孤立，经验无法沉淀为普适原则，普适原则也无法回到具体证据接受检验。而没有机制约束的提炼会失控：产物增殖、证据断链、原则与实例脱节后无人知晓。

**分项**：
- R9.1 派生可表达：记录间可声明派生关系（实例 → 规则 → 原则）。派生关系是显式的类型化引用，其结构由类型声明定义（不同域的层级形状不同：反馈→原则、日志→摘要、事实→手册）；层级不靠目录或标签暗示；
- R9.2 证据可追溯：提炼产物必须指明其证据基础（从哪些记录提炼而来），且能回答"这条产物从哪来"；反向关系由基础设施维护——删除或变更被依赖的记录时，依赖它的派生产物得到显式警示，不静默悬空；
- R9.3 收敛约束：提炼产物经由既有更新路径收敛到既有记录（同 R5.4），协议必须防止"每次提炼都新增产物"的记录增殖；提炼例程与维护例程（R5.5）同型：显式、有预算、经确认；
- R9.4 增量再提炼：支持以远低于全量的成本获知"某条派生产物之下，自上次提炼以来新增或变更了哪些证据"（R4.3 在派生关系上的应用），再提炼是增量的，不要求周期性全量重做；
- R9.5 层间冲突可见：一般原则与具体规则冲突时，基础设施不裁决语义（R5 的既有立场），但派生关系与具体程度差异必须可见，且类型约定可声明优先级规则（如"具体覆盖一般"）供执行体遵循；
- R9.6 原件不可侵：提炼是添加性的——实例记录保留原样，产物是新记录或对既有产物的更新；不存在后台自动改写（判断 5）；
- R9.7 产物新鲜度：提炼产物携带其证据截止信息（基于何时为止的证据提炼），使其可判断是否已落后于证据（衔接 R5.1/R5.2 的存疑策略）。

**责任边界**：状态层保证派生关系的完整、可见与可维护；提炼的质量（归纳是否正确、原则是否普适）是调用方约定与执行体的责任，不在验收范围内——"提炼之后证据链完整、可追溯、可收敛"在。

**验收**：
- 执行体能从多条实例记录出发，产出一条指回全部证据的原则记录；删除任一证据后，依赖警示可见；
- 重复执行提炼，产物收敛（更新既有原则）而非增殖；
- 新增一条证据后，无需全量扫描即可发现"某原则存在未消化证据"；
- 用户可以问"这条原则从哪来"，并获得完整证据链。

### R10 关键词检索与前端对等

**陈述**：执行体能以一个关键词查询为条件，在状态层**当前存活的记录**中定位"内容满足该查询"的记录——存活＝records/ 现存层；受管墓碑（删除后暂存于 attic/ 等待恢复的记录）与已消失记录不参与检索与过滤，经恢复接口回到 records/ 后恢复参与。查询由一个或多个空白分隔的词项构成（词项间组合语义见 R10.8，否定词项见 R10.9）。清单与检索结果可按类型声明声明的载荷字段值过滤（R10.10）。两个前端功能对等（R10.1）；该能力在其所属集成档内自足可用，其行为是确定性的、有预算的、新鲜的。

**动机**：用户记得的往往是内容片段（一个术语、一句规则、一个页码），不是它存在于哪个类型、哪条记录——按内容定位无法由"按已知结构过滤"替代。没有该能力时唯一兜底是全量导出后人工翻找，成本随库规模线性增长，正是 R4 要消除的形态。

**分项**：

- R10.1 前端功能对等：命令行前端具备的每一项工具与功能，工具协议前端均须对应具备；新增能力须同批落两端。两个前端只是指令入口形态不同（人敲命令 vs 执行体调工具），不构成功能支持差异。降级路径继续存在，但仅服务故障与连通性异常，不得成为常规操作路径（R8.9 的收紧）。最低对等清单为五项基础读能力（①摘要视图 ②清单与类型过滤 ③关键词检索 ④单条钻取 ⑤增量获知）加完整写路径。既有缺口如实分级——读路径：缺口为关键词检索（R10.2–R10.9 本期落地）；写路径：已知缺口为 merge（记录合并，属本条"完整写路径"最低清单，其映射实施登记入工具面定稿排期，不在本需求范围）；运维与工具盘点（bind、agenda/apply/fix、init 等）在设计阶段逐项裁决映射或豁免，不笼统豁免。view 为视图执行（读路径，按 id 取视图定义跑过滤并分页），工具协议前端已带同语义参数覆盖——两端均已可用，非对等缺口。本需求不断言对等缺口"仅"读路径一项。载荷字段过滤（R10.10）是本需求新增能力，非既有缺口，按本条原则同批落两端。
- R10.2 全域匹配（谓词逐域钉死，不留两可）：检索域覆盖记录承载内容的全部四个域，各域命中谓词如下：
  - 身份域：前缀——查询词折叠后作为记录身份键的**开头**出现即命中（身份是地址不是内容，故为前缀而非子串）；
  - 别名域：连续子串；
  - 载荷域：**逐值**连续子串——查询词折叠后在载荷的每个字符串值（含数组与嵌套对象中的叶子值）**内部**作为连续子串出现，即该值命中；键名不参与匹配（查字段名不命中，查字段值命中）；
  - 正文域：连续子串，且以正文字节**是合法 UTF-8** 为参与前提——正文区非合法 UTF-8 的记录，其正文区不参与匹配，其余三域照常（与 R11.4 的检索不受染一致；现状实现为有损解码后匹配，属 R11 已否决的伪命中形态，由 R11 落地时收口）。
- R10.3 完备召回：凡满足查询匹配条件（R10.2/R10.8/R10.9）的**存活记录**必须全部可达（经分页续读穷尽，不重复）；命中集合与"对真相层现存可判定记录逐条执行同一匹配"的结果一致——记录域为 records/ 现存层（attic/ 与已消失记录不参与，恢复后恢复参与），正文域以合法 UTF-8 字节为参与前提（R10.2 的例外子句同此适用）。索引等加速结构只允许影响速度，不允许改变命中集合。完备召回**限定于可判定记录**：格式损坏、无法解析的记录不进入正常命中集合（R6.2 的跳过在检索上的具体化），但不得静默消失——必须以独立告警暴露其位置、不可判定原因与修复入口，告警同样受 R10.6 新鲜承诺约束；经修复恢复可判定后恢复参与检索。
- R10.4 折叠等价：检索不因大小写与等价字符形式漏检（"Abs"与"abs"互可检出）；折叠规则单源，与身份键路径推导所用一致。
- R10.5 预算与确定性分页：清单、检索命中、过滤结果等**一切读结果形态**一律分页——单次返回规模有确定上限，超限必须显式标注并给出续读方式，命中总量不得转化为调用方单次的上下文消耗（R4.2 的读路径应用）。分页顺序确定——同一库同一查询两次检索（其间无写），命中序列完全一致。
- R10.6 新鲜即时：检索反映此刻真相层状态——记录被外部修改后，不执行任何维护动作即可被检索命中；不存在"已知可能漏掉刚发生写入"的检索路径。
- R10.7 定位与钻取分离：检索返回命中清单（定位信息与钻取入口，含身份与并发令牌），不携带全文；全文经单条钻取获得（R4.1 分层的既有语义）。
- R10.8 多词与：查询可由空白分隔的多个词项构成；记录须包含全部肯定词项（各词项按 R10.2 的逐域谓词命中——身份域前缀、其余域连续子串）且不包含任何否定词项（R10.9）方为命中。仅含一个肯定词项的查询，命中语义与既有单串检索一致。分词器不因此引入——每个词项仍按逐域谓词匹配，不引入词元概念。
- R10.9 否定词项：词项可携带否定标记（标记的语法形式归设计阶段），其匹配串按 R10.2 的逐域谓词在全部域均不命中时该否定词项满足。带否定词项的查询须至少含一个肯定词项；纯否定查询不构成有效检索，须被明确拒收——拒收须为显式错误响应，不得表现为空命中清单或全库清单。否定词项不改变完备召回：命中集合仍与"对真相层现存记录逐条执行同一匹配"一致（R10.3）。
- R10.10 载荷字段过滤：清单与检索结果可按载荷中声明的字段值过滤（起源场景如"知识板块=几何""条目形态=法则"）。过滤由**类型声明驱动**：类型声明指明本类型哪些字段可过滤及取值形态；基础设施只实现"按声明解释并执行"的通用机制，对具体类型零知识（与 R8.2/R8.4 相容）。过滤可与关键词查询组合（词项与 + 字段条件同时生效）；过滤结果同等受 R10.5 预算分页约束，命中定义与 R10.3 的记录域与匹配前提一致。类型声明变更后，既有记录的过滤服务降级标注、不拒绝服务（R8.7 的应用）。

**责任边界**：本需求保证**确定性检出**——"字符串存在则可检出"。不承诺相关度排序（最相关的排最前）、不承诺意图理解（同义、翻译、语义扩展）。检索质量属于判断型行为，归类型约定与执行体（判断 2 的既有划分）。

**验收**：

1. 仅具备完整工具协议档的宿主（无命令行、无文件系统访问），完成"关键词 → 命中清单 → 钻取单条 → 依载荷溯源（如教材页码）"全链路，全程不触发降级路径；
2. 在身份/别名/载荷/正文分别构造含查询词的记录：身份域用"id 前缀＝查询词、内容域不含该词"的记录（命中）与"id 中段含查询词、内容域不含该词"的记录（不命中——身份域为前缀）；载荷域另构造"键名含查询词、值不含"的记录（不命中——键名不参与）；检索可经续读穷尽全部命中且无重复；不含查询词的记录不出现；
3. 外部增/改/删三态，均不做任何维护动作、直接检索：外部新放入一条含查询词的记录文件——即命中（覆盖"发现索引外新文件"）；外部手改某存活记录正文加入查询词——即命中；外部删除一条命中记录（受管删除进 attic 与不经接口直接删文件两种各构造一次）——即不再命中且无残留；
4. 命中数超预算时响应显式标注并给出续读方式，按续读可读完剩余命中；
5. 同一库同一查询连续两次检索（其间无写），命中序列完全一致；
6. 构造仅含词项 A、仅含词项 B、同时含 A 与 B、均不含的记录各若干，以空白分隔查询"A B"检索，仅"同时含 A 与 B"的记录命中，且可经续读穷尽；
7. 构造"含 A 含 B""含 A 不含 B""不含 A"的记录各若干，以否定词项查询"A NOT B"检索，仅"含 A 不含 B"的记录命中且可经续读穷尽；纯否定查询被明确拒收——拒收须为显式错误响应，不得表现为空命中清单或全库清单；
8. 按类型声明声明的载荷字段过滤清单与检索结果，仅返回匹配记录且可经续读穷尽；与关键词词项组合时两者同时生效；
9. 前端对等抽验：命令行前端的每项读取能力在工具协议前端均有对应入口（本期核验面为检索与过滤；全量盘点随工具面定稿收口）；
10. 身份看似命中但记录损坏（如文件名以查询词开头、内容不可解析）：正常结果不含该条，独立告警可见（位置、不可判定原因与修复入口），读取不崩溃且可经接口修复。

### R11 二进制内容承载

**陈述**：状态层能以记录形态承载非文本内容（图片等二进制数据）：写入的字节与读回的字节完全一致；图可被其他记录以类型化引用关联，关联与删除语义确定；宿主能按需取回字节；图的存在不推高文本内容的访问成本，也不污染检索；字节损坏可被发现并治愈。

**动机**：知识资产的原始形态不全是文本——题库的配图、签名的扫描件、录屏与音频片段，字节本身就是载荷。承载不了二进制的状态层，把这类资产排除在外，等于宣布"第二记忆只记文字"；而绕开系统把图放旁门外，图的版本、删除、引用、迁移全部脱离机制管辖，正是状态层要消除的碎片化形态。

**分项**：

- R11.1 受管形态：二进制内容以记录形态入库，完整享有信封机制——身份与并发令牌、写入留痕、删除隔离（删除＝移入隔离区而非消失）、引用完整性；跨机器迁移仍等于复制目录。
- R11.2 字节保真：写入字节与读回字节完全一致；**机制自身导致的内容改变**只能来自经受管接口的**内容写操作**（损坏恢复即属此类，见 R11.6）——因此机制的再生成、结构修复及一切不针对内容的维护操作不得改变正文字节；人手整文件替换及其他外部直写仍为合法输入（R2.2/R2.4），按 R3.5 如实可见、R6 识别与收敛，不在本条约束范围；保真对两个前端的写与读同样成立——写入按原始字节落盘，取回按原始字节交付（线路上的传输编码只是保真通道，宿主解码所得与盘上字节一致）。
- R11.3 关联确定：引用方对图的引用是类型化引用，以引用方类型声明的引用字段（x-ref 镜像纪律）建立为主、link 边为通用兜底；两条路径的完整性与删除语义均按既有引用机制（默认阻止删除被引用者、显式越权留痕）；"谁引用哪张图、删掉一边另一边如何"的答案确定且可见——越权删除后的依赖警示经校验例程（verify 的悬空引用报告，两前端一致，覆盖上述两条建立路径）可见，不做读路径实时标注。
- R11.4 文本路径不受染：图的存在不推高摘要、清单、单条钻取文本记录的返回规模（预算按记录独立计，一条题不因带图变贵）；关键词检索不因二进制正文产生伪命中——查询词命中图记录的编码巧合不进入命中清单（与 R10.2 正文域的合法 UTF-8 参与前提一致）。
- R11.5 取回对等：图字节取回是两个前端的同批义务（R10.1 前端功能对等）——完整工具协议档不经文件系统访问即可完成"定位题目→钻取→取回其图字节"全链路；命令行前端经接口通道取回原始字节（不要求文本形式呈现，如正文落至指定文件一类通道），不依赖人手直接读记录文件或文本解码。
- R11.6 损坏可治愈：图字节与历史不符可被校验面发现——发现按既有摘要对账审计的分档承诺（深档审计做磁盘与事件日志的摘要对照，天然覆盖二进制记录；浅档校验不做摘要对照）；存在经接口的修复路径：损坏内容的恢复是**经确认的内容写操作**，允许以历史或备份字节替换当前正文，产生新版本并留审计痕（不违反 R11.2——该条约束的是不针对内容的操作）；损坏的图记录不使任何读取路径崩溃。

**责任边界**：状态层保证**字节保真与关联完整**。不承诺：图内容的理解（OCR、图生文——判断型行为，归执行体能力与类型约定）；图的体积优化（压缩、转码、缩略图——存入什么字节就取回什么字节）；"能用文本格式就别用位图"之类的表达劝退（归图片类型约定文档的教学，按 R7 强制与教学分离）。对 R2.2 的例外（其唯一明文例外，见 R2.2）：人用文本工具对图记录可审计其存在与全部结构信息（结构头可读、大小可查、来源可溯），内容字节的修改经接口或人手整文件替换完成；人手整文件替换需按规范重建结构头并遵守字节确定性，超出非专业用户的日常操作面——日常修复走接口替换，整文件替换是了解格式的用户的兜底通道。

**验收**：

1. 带图题库全链路：导入含图题目（题目记录＋图记录＋引用边），将存储目录整体复制到另一台机器，每张图字节与源机逐一哈希一致；
2. 对任一图记录执行结构修复（结构头再生成、正文按字节保持），图字节哈希不变；
3. 删除被题目引用的图：默认被阻止且明确报告依赖方；越权删除后运行校验例程（verify），题目侧的悬空引用报告可见（覆盖类型声明引用字段与 link 边两条建立路径），不静默悬空；
4. 仅具备完整工具协议档的宿主（无命令行、无文件系统访问），完成"定位题目（检索或类型过滤）→钻取→取回图字节"，字节与写入时一致；
5. 检索对二进制正文的排除边界（仅正文区排除，与 R10.2 正文域参与前提一致）：(i) 构造正文区含"abs"编码巧合、身份/别名/载荷均不含的记录——不进命中清单，命中集合与移除该记录后的等价库一致（构造须保证编码巧合确在正文区，防测试空转）；(ii) 构造载荷（如文件名含"abs"）或别名含"abs"的记录——仍命中，锁定"仅正文区排除"边界；(iii) 正文区为合法 UTF-8 的图记录（如 SVG 文本）照常参与检索；
6. 人为翻转某图记录正文区一个字节：深档校验（verify --deep）报告该记录磁盘摘要与事件日志不一致（发现半边按既有分档承诺；非 deep 校验不做摘要对照）；经接口执行内容恢复后，正文逐字节等于**所选的历史版本或备份来源**，修复产生新版本并留审计痕，复跑深档校验不再报告该记录摘要漂移；全部读取路径不因此崩溃；
7. 前端对等抽验：命令行前端经接口通道取回图字节（不经人手直接读记录文件、不经文本解码），字节与写入时哈希一致（对应 R11.5 的对等义务）。

## 4. 需求赖以成立的五个判断

以下判断是 R1–R11 的二阶前提。它们本身可辩论；推翻任一判断，对应需求需要重估：

1. **主要消费者是模型，人是审计者与兜底。** 接口以文本与结构化数据原生态为主，不要求图形界面；但人的可读可编辑性是硬需求（R2），不是可选项。
2. **确定性机制与智能行为是不同的工程对象。** 二者的成本模型、失效模式、测试方法完全不同，需求因此要求分离交付（R7）。
3. **检索精度需求与库规模相关。** 在小到中等规模下，"结构化摘要即索引"视为达标；本需求不强制引入语义检索基础设施，由 R4 的验收标准在规模增长时驱动升级。（注记：R10 的确定性关键词检索使"按内容定位"在该规模带内不再依赖结构化摘要的措辞质量，本判断对语义检索的立场不变。）
4. **主动注入是宿主侧能力。** 本需求以"可触发的读取协议 + 约定"表达召回，不强求基础设施主动推送；宿主具备注入能力时按 R8 渐进增强。
5. **质量维护是显式成本。** 维护必须可见、可预算、经确认（R5.5）；无人监督的后台自动改写用户记忆，因不可审计而不可接受。

---

## 5. 范围划界（明确不要求的事）

- **不要求图形界面**（判断 1）；
- **不承诺记忆完美**：要求的是可验证、可修复，不是永不出错（R5）；
- **不强制语义检索基础设施**（判断 3）；
- **不强制主动上下文注入**（判断 4）；
- **不要求文本工具可直接编辑二进制内容**（R11：二进制记录降格为可审计＋经接口替换）；
- **不预设实现形态**：存储格式、访问协议、组件边界、宿主适配方式均由后续方案阶段决定。本文档只约束必须成立的性质——任何方案只要满足 R1–R11 即为合理解。

## 6. 整体成功判据

系统建成时，以下陈述全部为真：

1. 新执行体冷启动建立工作视图的成本有界且稳定，与状态总量无关；
2. 用户在不使用任何 Agent 工具的情况下，能读懂并修改自己的全部状态——文本类状态可读懂并修改；二进制记录按 R2.2 的可审计与替换例外处理；
3. 经受管接口的并发写入竞态下无静默丢失、无重复创建、无悬空引用；外部直写造成的修改与覆盖在下次访问时如实可见并可修复；
4. 状态总量增长一个数量级，单次访问成本上界不变；
5. 遵循约定的执行体能在有限步内发现并修正一条过时记忆；
6. 注入任意数量的坏数据，服务不崩溃，且坏数据可经接口修复；
7. 新增一种内容类型不需要修改基础设施代码；
8. 能力最弱的宿主环境仍能完成完整的状态闭环；
9. 执行体完成的提炼产物携带完整证据链；证据变更或删除时，受影响的产物可被发现；
10. 执行体能以关键词查询按内容定位记录，两个前端能力对等且命中完备、确定、新鲜；
11. 图等二进制内容以受管记录入库后字节保真、关联完整，检索与文本访问不因之受损，损坏可经校验发现并治愈。

## 7. 术语表

| 术语 | 定义 |
|---|---|
| 执行体 | 以 LLM 为核心、借助工具完成工作的自动主体；一次会话或一个进程是其一个实例 |
| 宿主 | 运行执行体的软件环境（编码工具、IDE、命令行工具等），集成能力各异 |
| 状态层 | 本文所述要建设的基础设施：独立于执行体存续，承载全部受管状态 |
| 记录 | 状态层中一条可寻址的信息单元（一条任务、一条记忆、一个知识条目） |
| 写入者 | 对状态层产生写操作的任何主体：执行体、进程或人 |
| 预算 | 对单次访问返回规模的机械上限，由基础设施强制 |
| 约定 | 以教学方式交付、依赖写入者理解与配合的行为规则 |
| 第二记忆 | 状态层的概念名称：Agent 的外置记忆，与易逝的上下文窗口相对 |
| 信封与载荷 | 记录的两层模型：信封是基础设施拥有并管理的公共字段（身份、类型、时间、版本、引用能力）；载荷是类型特有字段与自由正文，仅由类型声明解释 |
| 类型声明 | 描述一种受管内容类型的声明物：可执行的结构定义（含校验强度分档）与约定文档，见 R8 |
| 派生关系 | 记录间"从哪些记录提炼而来"的类型化引用（实例 → 规则 → 原则），由基础设施保证完整与可见，见 R9 |
| 提炼 | 调用方执行体依据约定、从既有记录归纳出更一般记录的行为；状态层为其提供派生结构与收敛约束，不承担提炼质量 |
| 词项 | 查询中空白分隔的检索单元，按逐域谓词匹配（身份前缀、其余域连续子串）；多词项"与"组合、可带否定标记（R10.8/R10.9） |
| 前端功能对等 | 命令行前端具备的每项工具与功能，工具协议前端均须对应具备；新增能力须同批落两端；入口形态不同不构成能力差异（R10.1） |
| 载荷字段过滤 | 按类型声明声明的载荷字段值筛选清单与检索结果；基础设施按声明解释执行，对具体类型零知识（R10.10） |
| 字节保真 | 写入字节与读回字节完全一致，且**机制自身**导致的内容改变仅来自经确认的内容写操作——机制的再生成/结构修复/不针对内容的维护不改变正文字节；人手整文件替换与外部直写为机制外合法路径（R2.2/R2.4/R3.5）（R11.2/R11.6） |
| 伪命中 | 查询词与二进制字节编码形式的巧合子串匹配——非内容语义的命中（R11.4） |
| 真相层 | 记录文件的存储层，一切读取的最终裁定者（R3.5"外部修改收敛"的载体） |
