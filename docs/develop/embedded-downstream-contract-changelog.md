# 嵌入式下游契约变更记录（候选）

> **状态：维护者已接受的 `1.0.0` 候选，未发布。** 维护者已选定首个稳定契约版本号 `1.0.0`，并于 2026-11-22 接受当前分支候选。本记录对应当前工作树中的候选实现，不构成已发布承诺；核验历史对外承诺并另行授权发布后，才可将其归档为正式版本条目。

## 1.0.0 · 首个嵌入式下游契约候选

### 新增

- 引入店基础格式标记 `spacememory/2` 与整店 `required_features` 清单。数字格式 `1` 可显式只读；升级通过停机迁移完成。
- 增加候选 Rust API 清单和只读消费者示例；编译期消费者探针逐项核对 mem-core 与 mem-index 稳定候选入口，见[API 候选契约](embedded-downstream-contract-api.md)。候选文档列出 MCP 工具名，测试逐项比较文档与运行时工具表，避免接口清单漂移。增加机读能力文件，描述读写格式、只读格式、支持特性、读兼容特性和本次发布证据状态。
- `WriteContext` 通过构造器和 builder 配置；下游可读取结果/错误类型和可扩展输入枚举采用 `non_exhaustive`，包括 `RestoredBody` 与 `RestoreSource`。消费者示例编译核对正文恢复结果字段读取、来源枚举通配匹配、冲突令牌读取及错误/迁移状态的通配匹配。`AddArgs` 的 1.0 字段集合与 `OpenMode` 的 1.0 变体集合由消费者编译探针锁定；字段或变体增删/改型按 MAJOR 变更处理。并发测试暂停钩子从稳定候选输入移出，仅在 debug 测试辅助入口可用。
- 记录 API、行为、店格式及共店承诺的 SemVer 升号政策；每个正式发布点须附不可变 tag、对应能力表、行为证据和变更记录。

### 行为与兼容性

- 每个受管写入口在跨进程维护门闩内重读磁盘格式和必需特性；特性登记使用独占门闩、以最新配置为基准合并，成功返回后才允许依赖该特性的写入。
- 首个可选机制特性为 `event.restore_body/v1`：正文恢复在同一独占许可内先登记，再发布更新记录及 `restore_body` 事件；迁移旧店时依据已有事件历史补登该特性。未执行正文恢复的店保持空清单，不因升级自动失去旧写者兼容性。
- 既有 Store 句柄在公开真相层读取前后复核磁盘兼容状态。未声明只读兼容的缺项拒绝读取；声明可读的缺项只能走真相层直读，不能使用派生索引证明。
- 配置、会话、agenda、事件、pending、索引、checkpoint、sidecar 与显式 reconcile 写入纳入受管许可。只读读取不应创建台账目录或触发持久化维护。
- MCP 与 CLI 共用受管机制层；本候选只列已验证工具名，不承诺尚未验证的跨版本共店组合。

### 迁移与恢复

- 提供首次 `1` 到 `spacememory/2` 的显式停机迁移。迁移先深度预检并保留未知配置键，以单次原子配置切换作为完成点；重复执行识别已迁移状态，不清空已有特性。
- 迁移前由部署方停止并隔离所有旧进程、关闭句柄，并在店外建立完整备份。失败恢复或回退必须从完整备份恢复到独立目录；禁止仅把格式标记改回 `1` 后启动旧写者。
- 自动化测试覆盖迁移切换前后进程终止、重试、已迁移识别、未知键保留、拒绝条件下不变更，以及保留旧索引和检查点时拒绝旧证明。另以历史源码构建（commit `8026d0d9f2fdb0252bff5405a982e9927299a418`，macOS release `mem 0.1.1`）创建真实数字格式 1 样本店，由候选 CLI 迁移并验证完整备份和旧二进制恢复读取；该样本不代表正式发布二进制或生产店。

### 验证状态与已知限制

- 当前候选的全工作区测试、全目标检查和 release 库/二进制/示例检查已在 macOS 开发机通过；Windows 目标和运行时验收尚未完成。
- 当前候选已登记 `event.restore_body/v1`，正文恢复与旧格式迁移的正向登记回归通过。不同特性并发求并仍需第二个有实际机制语义的特性后验证；登记完成、依赖写入前崩溃和写入中断矩阵仍按 T04 扩展验收。
- 当前没有稳定发布 tag、正式历史发布二进制矩阵、真实生产历史店迁移演练、远端 tag 保护证据或下游 SpaceTeam POC；`validated_coexistence` 保持空数组。这些范围不得在正式能力清单中标为支持。
- 本候选已由维护者接受为 `1.0.0` 实现候选，但尚未成为正式 API 发布或产品发行；实际发布资产、不可变 tag、外部验收与发布授权仍待完成。
