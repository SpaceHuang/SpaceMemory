### 0.1 待批准清单（本轮批什么）

七项决策 + 方案整体可实施性。逐条全文见 §3（六要素齐全，可单独摘出裁决）：

| # | 决策 | 一句话 |
|---|---|---|
| ① | 查询文法 | 词项按 Unicode 空白切分；否定标记 = 半角连字符 `-` 前缀；空查询与纯否定查询显式拒收 |
| ② | 跨前端一致性机制 | 检索执行器单源下沉 mem-core；索引经"构造即证明"注入——open_proved 唯一证明点（stat 咨询 ∧ 只读打开 ∧ schema 门禁含 bad_records ∧ epoch 同代核对），CLI 与 MCP 两前端同源调用 |
| ③ | 可过滤字段声明词汇 | 属性级 `x-filter: true`，取值形态由该属性的 schema 本体承载；词汇表版本 1→2 |
| ④ | 过滤等值语义 | 规范过滤条件 = 字段＋标量文本（CLI 原样、MCP filters 值一律 JSON 字符串），两端条件空间逐字相同；字符串折叠等值、数字按 JSON 数值文法解析等值、布尔认 `true`/`false`、数组任一元素；同名字段异形按"兼容类型集"逐类型解释（合并命中，子集经 `--type` 收窄），兼容集为空显式错误 |

| ⑦ | 坏记录告警承接 | find/list 响应透出扫描/物化期收集的全量坏记录告警（rel 升序截断、上限 200、截断标注、verify 续读）；indexed 经 bad_records 表（同扫描同事务、检查点覆盖全部文件）；缺表/不可证一律回退 direct，禁止空告警的 indexed |

### 0.3 自曝三处（作者认为最可能被推翻的点）

1. **决策②的"构造即证明"形状**（open_proved 唯一证明点 + trait 只承载已证明句柄的查询）。推翻证据：评审给出更轻的组装点——例如把双执行器与证明整体放入一个独立薄 crate，或调整 crate 依赖方向后 trait 面可以更窄/更宽。届时改的是"单源住在哪、证明如何收口"的工程形态，"单源 + 证明唯一执行点"结论本身不受影响。
2. **决策③④的过滤词汇、等值语义与输入规范形态**（属性级 x-filter + 折叠等值 + 规范条件 = 字段＋标量文本、MCP filters 只收 JSON 字符串）。推翻证据：评审举出第二个真实类型无法用属性级自然表达其过滤需求（如需要嵌套字段、跨字段条件、值域开放语法）；或用户声索大小写敏感的过滤（"AI"与"ai"须为不同板块值）；或 MCP 宿主普遍习惯传 JSON 原生数字/布尔、显式拒收实测成为高频摩擦——届时输入形态须回炉为两端显式类型语法（决策④选项 (b) 形态），等值语义与兼容集规则可保留。届时过滤面回炉；检索面（①②⑥⑦）不受牵连。
3. **决策⑦的全量告警**（不做查询相关化）。推翻证据：实际库中坏记录常态化超过十余条时，每次 find/list 都携带一批与本次查询无关的告警，评审判其为噪声负担。届时改为"仅身份前缀似命中的坏记录才报"（需引入文件名启发式，见 §2.5 的反对理由）或告警独立分页。

## 2. 方案

### 2.1 执行器单源与调用链（决策②）

**折叠**：大小写与等价字符形式的归一（NFC + Unicode 小写映射，单源 `paths::fold`）——检索词项、过滤值、索引折叠列三面共用同一函数（R10.4 的"折叠规则单源"由此机械成立）。**粗筛/精筛**：索引先用 SQL 近似条件取一个"只会多不会漏"的候选超集，再对每个候选回读记录文件、用命中谓词单源逐一精确判定——语义永远由精筛裁定，粗筛只影响速度。**快路径/直读**：仅当索引新鲜性可证明（检查点 stat 一致 ∧ OS 变更日志订阅无缺口）时走索引，否则全量直读真相层并标注——不存在"已知可能返回旧值"的路径。

检索执行器从 CLI crate 下沉至 mem-core（新增 `find` 模块，或并入既有 `search.rs`——模块归属是实施自由度，职责边界如下固定）：

```
输入：原始 query 字符串 + 过滤条件列表 + limit/offset + 注入的 Option<&dyn FindPrefilter>
 1. parse_query（§2.2）                → 肯定/否定词项；空查询、纯否定 → 显式拒收
 2. 过滤条件声明校验（§2.4）            → 候选类型集内无兼容声明/重复字段/兼容集为空 → 显式拒收
 3. 索引可用性：经 open_proved"构造即证明"（见下）——Some(已证明句柄) → indexed；None → direct 并标注
 4a. indexed：FindPrefilter.candidates(正词项折叠串, 候选类型集) → 超集候选（modified DESC, id DESC）
     → 逐候选回读真相层（文件已消失 → 跳过）→ 精筛（组合谓词 ∧ 过滤）→ 告警取自 bad_records(cap)；
     candidates/bad_records 任一返回 Err → 放弃本次 indexed 应答、回退 4b 全量应答，reason 携带真实错误
     ——不得把失败转为空命中或空告警
 4b. direct：ops::scan_all 全量直读 → 同一精筛 → 告警取自扫描收集(cap)
 5. 命中序分页：offset = 命中序号（非扫描偏移）→ hits / truncated / resume / warnings
```

调用链（两前端同源）：

```
  mem find（CLI）           mem mcp → mem_find（MCP）
       └────────────┬────────────┘
                    ▼
        mem-core：find 执行器（单源）
   解析词项 → 过滤校验 → fastpath 判定 → 精筛（谓词单源 ∧ 过滤执行器）→ 命中序分页
        │ indexed（拿到已证明句柄）             │ direct（否则，零写盘）
        ▼                                   ▼
  FindPrefilter（trait，mem-core 定义，      ops::scan_all 全量直读
  仅承载已证明句柄的两个查询）                  │
   · candidates：多词项折叠列 LIKE 合取粗筛    逐记录同一谓词+过滤
   · bad_records(cap)：rel 升序坏记录清单         │
        │ 超集候选                              │
        ▼                                      ▼
     逐候选回读真相层 → 同一谓词精筛 ←──────同一函数

  open_proved（mem-index，唯一构造/证明点——两前端调同一函数）：
   stat 咨询（freshness 既有：检查点 ∧ 订阅覆盖）→ 只读打开（不建库不建表）→
   只读 schema 门禁（records/refs/meta/bad_records＋折叠列完整）→
   epoch 代际核对（checkpoint.index_epoch == 索引当前 epoch）；
   全过 → Some(ProvedIndex)；任一失败 → None——不存在"未证明的 indexed 执行器"
```

**多词项粗筛的下推规则**：每个**正词项**生成一组 LIKE 条件（id 前缀 ∨ 三折叠列含匹配），多词项之间用 AND 连接——每个词项的 LIKE 条件都是其谓词命中的超集（载荷折叠列是全部值的折叠拼接：值内命中 ⊆ 拼接命中，跨值假命中只会多不会少；id 前缀 LIKE 与谓词同形），各自超集的交集仍是超集。**负词项与过滤条件一律不下推**：LIKE 命中不代表记录命中（跨值假命中），对近似条件取反会把真命中错误排除——负词项与过滤只在精筛阶段对完整候选集施加，故不影响召回完备（R10.3/红线8）。

**构造即证明（快路径的唯一证明点）**：`mem-index::open_proved(store, hello) -> Option<ProvedIndex>`——stat 咨询（mem-core freshness 既有通道：检查点 ∧ 订阅覆盖）→ 只读打开 index.sqlite（不建库不建表，红线18）→ 只读 schema 门禁（records/refs/meta/**bad_records** 及折叠列完整，旧代索引缺表即不通过）→ **epoch 代际核对**（checkpoint.index_epoch == 索引当前 epoch，防旧检查点配到删除重建/未完成物化的新索引；既有 CLI 快路径已做此核对，commands/mod.rs:301-305，随下沉完整收进而非省略）。全部通过才返回 `Some(ProvedIndex)`；`ProvedIndex` 只有这一条构造路径，并实现 mem-core 的 FindPrefilter：

```rust
pub trait FindPrefilter: Send + Sync {
    /// 超集候选：正词项折叠串合取（可为空 = 无文本条件）+ 可选类型收窄
    fn candidates(&self, terms_folded: &[String], types: Option<&[String]>) -> Result<Vec<PrefilterRow>>;
    /// 坏记录清单（rel + 原因）：rel 升序最多 cap 条 + 是否还有更多
    fn bad_records(&self, cap: usize) -> Result<(Vec<(String, String)>, bool)>;
}
```

证明逻辑不出现在 trait（epoch/schema 门禁在构造函数内完成）、不进入执行器（分流依据只有一个："是否拿到已证明句柄"）、不留在前端（CLI 与 MCP 前端循环调用同一 open_proved 组装，调用点不承载新鲜性判断）。indexed 执行中 candidates/bad_records 任一返回 Err → 放弃本次 indexed 应答、回退 direct 全量应答，read_mode=direct + reason 携带真实错误——不得转为空命中或空告警。

既有 `Index::search`（单串 LIKE）被 `candidates` 取代；既有 fastpath 测试（含"索引删除重建但检查点仍指旧代"回归）经新路径保持全绿（行为等价迁移）。下沉后 MCP 的 list/find 同样获得快路径（当前 MCP list 恒直读）——命中面等价由单源结构性保证，`read_mode` 标注可能因路径不同而不同，不作对等断言对象。

### 2.2 查询文法（决策①）

query 是**单个参数**（CLI 一个 argv、MCP 一个 JSON 字符串），含空格的整串由调用方引号包裹或 JSON 原样传递；词项切分全部在机制内完成——不依赖 shell 分词，两前端同一解析。

```
query    := 词项 (空白 词项)*
词项      := 肯定词项 | 否定词项
否定词项  := "-" 后随至少一个字符（仅半角 U+002D；全角连字符不是标记）
肯定词项  := 不以 "-" 开头的非空串，或恰为 "-"
```

- 空白 = Unicode White_Space（Rust `char::is_whitespace`；含 U+3000 全角空格——中文输入法友好）；
- 否定词项的匹配串 = 去掉前导 `-` 后的原串（`--x` = 否定词项，匹配串 `"-x"`）；恰为 `"-"` 的词项 = 字面肯定词项；
- 每个词项匹配前折叠一次（执行器层折叠，逐记录循环内不重复折叠——沿既有约定）；
- **空查询**（空串/仅空白）与**纯否定查询**（无肯定词项）→ 显式错误 `query_invalid`（"查询须至少含一个肯定词项"）——CLI 非零退出 + JSON 错误体，MCP JSON-RPC error（沿各自既有错误通道，data 携带 `kind`）；**绝不**表现为空命中清单或全库清单（R10.9）；
- **登记边界**：以 `-` 开头的字面肯定词项不可直接表达（`-font` 无法作为正词项查询）。缓解：子串语义下去掉前导连字符查询（`font`）仍命中含 `-font` 的记录，代价是混入所有含 `font` 的记录。该边界随未来"短语精确语法/域限定"（基线未来清单）消除。

### 2.3 命中语义与正文前提收口

**组合谓词**（外层包装，谓词本体不变）：

```
命中(r) := ∀p ∈ 肯定词项: record_matches(r, fold(p))
        ∧ ∀n ∈ 否定词项: ¬record_matches(r, fold(n))
```

`record_matches` 四域谓词（身份前缀 ∪ 别名子串 ∪ 载荷逐值子串 ∧ 键名不参与 ∪ 正文子串）**不动**——R10.2 已逐域钉死并裁决追认现状。仅含一个肯定词项且无否定词项时，组合谓词与既有单串检索逐记录等价（R10.8 的回退语义）。

**唯一改动：正文域参与前提收口**（R10.2 正文域条款，同时是 R11.4"检索不受染"的检索侧落地）：

```
旧：fold(&String::from_utf8_lossy(body)).contains(q_fold)
新：match std::str::from_utf8(body) { Ok(text) => fold(text).contains(q_fold), Err(_) => false }
```

正文区非合法 UTF-8 的记录，其正文域退出匹配，身份/别名/载荷三域照常——现状的有损解码匹配属需求已否决的伪命中形态，随本方案收口，不等 R11 其余部分。

### 2.4 载荷字段过滤（决策③④⑤）

**声明词汇（type-declaration.md v1.1 草案行，随实施落修订表）**——§1.1 词汇表新增第 7 个关键字：

| 关键字 | 位置 | 语义 | 强制点 | 归类 |
|---|---|---|---|---|
| `x-filter`: `true` | payload 属性 | 声明该字段值可作清单与检索的过滤条件；取值形态 = 该属性本体的 schema 定义 | mem-core 过滤执行器 | (a) |

配套规则（草案）：`x-filter` 点名的属性必须存在于 `properties`（verify 对点名缺失的检查同族扩展）；支持形态之外的属性声明了 `x-filter` → verify 告警 `filter_shape_unsupported`，运行时对该字段过滤 → `invalid_filter_value`；词汇表版本 KEYWORD_VOCAB_VERSION 1→2。

**v1 支持形态**：`string` / `number` / `boolean` / 元素为以上标量的 `array`（任一元素等值即命中）。嵌套对象、跨字段条件、值域语法不在 v1（基线未来清单）。

**等值语义**：string → 折叠等值（与检索共用折叠单源——"Geometry" 与 "geometry" 互可检出过滤）；number → 数值等值；boolean → 字面等值；array → 任一元素按其形态等值。

**声明检查与同名字段多声明（按候选类型集，唯一规则）**：候选类型集 = type 参数/view 限定到的类型集，未限定时 = 全店已加载类型集。

- 候选集中**无任何类型**声明该字段 → 显式错误 `unknown_filter_field`（防手滑打错字段名得到静默空结果）；
- 有类型声明 → 逐类型解释：**规范过滤条件 = 字段＋标量文本**（两端同域，见"取值转换"）；**兼容类型集** = 候选类型集中、能按自身声明解释该文本的类型集合——string 声明按文本折叠等值；number 声明按 JSON 数值文法严格解析成功后数值等值（"1" 与 "1.0" 同值）；boolean 声明仅认文本 `true`/`false`（大小写敏感）；标量数组声明按元素形态同前、任一元素等值即命中。兼容类型集为空 → `invalid_filter_value`（含空文本）；
- 过滤生效于兼容类型集中的类型；**未声明与声明但不兼容**的类型，其记录一律不命中、不报错——与"未声明类型静默排除"是同一条语义（按声明解释）的自然延伸；
- **精筛按每条记录自身类型的声明裁定等值**（记录属于类型 T，就用 T 的声明解释该字段值与过滤值）——跨类型同名字段异形（如 A.status 为 string、B.status 为 number）时，一次过滤对能解释该值的类型各自生效，不因异形拒绝整个请求；
- 同一字段重复给出 → `duplicate_filter_field`。

**取值转换（规范条件 = 字段＋标量文本，两端同域）**：CLI 的值原样即文本；MCP `filters` 的值**一律为 JSON 字符串**——传入数字/布尔等非字符串 JSON 标量 → `invalid_filter_value`（附说明"值须为字符串文本，类型解释由字段声明承担"）。文本的解释完全由声明承担（每个声明该字段的类型各自解析，见上），因此**两端的合法条件空间逐字相同**：CLI `--filter status=1` 与 MCP `filters:{"status":"1"}` 是同一个规范条件，必得同一命中集——异形同名（A 为 string、B 为 number）时同为"A∪B 合并解释"，不存在只有一端能表达的过滤语义（对等判据）。**子集表达**（只要 A 或只要 B）两端同由 `mem list --type <t>` 收窄候选类型集承担（find 的类型限定是基线未来项）——合并与子集在两端各有同径入口。

**降级承接（R8.7/R10.10）**：清单与检索主体永不因过滤而拒绝；被拒绝的只是不合法的过滤参数。类型声明变更后：字段仍被声明 → 既有记录按其实际载荷值照常过滤（旧数据零影响）；字段不再被任何候选类型声明 → 该过滤参数显式错误（主体读服务照常）；记录侧字段缺失或形态不符声明 → 该记录不命中，不计为错误。类型目录整体删除 → 该类型记录仍进清单与检索（信封级操作），其记录视同未声明类型处理。

**两路径执行**：与 find 同构——indexed 经 `candidates(terms, 兼容类型集)` 收窄后逐候选回读精筛（多个过滤条件时收窄 = 各条件兼容类型集的**交集**；纯词项查询无类型收窄）；direct 全量扫描逐记录判定。indexed 按类型收窄是正确性无害的加速：被收窄排除的类型，其记录在精筛必不命中（未声明、不兼容或被其他条件排除）。

### 2.5 坏记录告警（决策⑦）

R10.3（v1.4 口径）：格式损坏、无法解析的记录不进正常命中集合，但不得静默消失——须以独立告警暴露**位置、不可判定原因与修复入口**。

- **来源同源（同一次扫描；检查点发布走既有协议）**：direct 路径 = `scan_all` 既有收集（"跳过不可读 / 跳过坏条目"，ops.rs:59-80）；indexed 路径 = **同一次物化扫描、同一事务**内把坏记录与正常记录一并落库——`bad_records(rel, error)` 表与 records 行同事务写入；**检查点不随该事务提前发布**——它复用该次扫描的 stat 集（**覆盖该次扫描看到的全部 `records/` 文件，含不可解析/不可读文件**），仍经既有收敛协议发布（物化后新鲜订阅查询为 0 才发布，`publish_converged_checkpoint` 既有路径，freshness.rs:201-235；规范 §5.5 检查点发布收敛纪律），**不新增第二条检查点发布路径**。检查点全覆盖是告警新鲜性的依据：坏文件在检查点后的任何外部变化（改好、更坏、删除）都造成 stat 失配 → 回退 direct → 告警如实反映。物化是写例程，不违红线18；读路径只读打开索引。
- **缺表即回退，禁止空告警的 indexed**：bad_records 缺表、结构不完整、读取失败，或经 open_proved 无法证明与检查点同代（§2.1）——一律不进入 indexed 应答，回退 direct 全量扫描并透出真实告警。`mem verify` 只作超限后的续读通道，**不替代本次响应的告警义务**（R10.3）。
- **透出**：find/list 响应新增 `warnings: string[]` 与 `warnings_truncated: bool`。告警文本三要素模板：`"跳过坏条目 {rel}：{原因}；修复入口：mem fix {rel}"`（不可读文件同型，原因与入口相应替换）。
- **上限与稳定排序**：两路径统一按 **rel 升序**排序后截断，上限 `list_limit_max`（200）；超限置 `warnings_truncated: true`，note 注明完整清单经 `mem verify`（不对告警做 offset 分页——告警是标注不是读结果主体）。排序先行保证 direct（扫描枚举序）与 indexed（SQL 序）截断出的子集逐条一致。
- **不做查询相关化**（v1 登记）："身份看似命中"须以文件名启发式判定——记录身份 id 在 frontmatter 内，坏记录恰恰读不出 id；带唯一键类型的文件名是 slug 不是 id，启发式在两类记录上行为不一致，且引入新的两可。全量收集下验收 10 的构造（文件名以查询词开头、内容不可解析）同样满足：不在命中清单 ∧ 告警可见。

## 3. 决策条目（六要素）

### 决策① 查询文法：否定标记 `-` 前缀 + Unicode 空白切分

- **背景**：需求已裁决查询由空白分隔的词项构成、词项可带否定标记（多词与、与位排除均已纳入本期），但标记的语法形式、空白定义与切分规则归设计。它决定两个前端共同的解析行为。
- **选项**：(a) 半角 `-` 前缀 + Unicode 空白切分；(b) `NOT` 关键字（如 `NOT` 大写作标记）；(c) `!` 前缀。
- **后果**：(a) 破坏了会怎么表现——想找以连字符开头的词（如命令行选项名 `-font`）时无法把它作为肯定词项直接查询；查 `font` 虽能命中 `-font` 所在内容，但混入所有含 `font` 的记录。(b) 破坏了会怎么表现——正文里本就有英文词 "NOT"：把它当普通词查询时会被当成运算词（或被迫先想转义）；大小写约定（仅大写算标记？）使 `not` 与 `NOT` 行为不同，用户记不住、文档要专门教。(c) 破坏了会怎么表现——常见交互式 shell 中 `!` 触发历史扩展：敲查询时漏了引号，执行的是另一条历史命令而不是检索。
- **可逆性**：语法是对外行为——发布后更换标记符属行为变更须评审；未发布前任意改。
- **依据强度**：已验证——现状 CLI 为单串无语法，无既有语法依赖要保（空白语义本身已是裁决过的行为变更）；`!` 的 shell 历史扩展为常识级行为。未验证——用户对否定写法的实际偏好（无数据）。
- **推荐 + 默认**：(a)。默认 (a)；边界（前导连字符正词项不可表达）随未来短语语法消除。
- 下钻：R10.8/R10.9；提案决策⑦（否定标记语法归设计的挂账）。

### 决策② 跨前端一致性：执行器单源下沉 mem-core ＋ 索引"构造即证明"注入

- **背景**：提案范围第 5 条要求同一查询两前端结果集合与顺序一致，机制保证方式（单源实现或一致性测试对账）归设计。现状双执行器与快路径判定（含代际核对）都住在 CLI crate，MCP（依赖方向所限）无法复用——不处理则 MCP 侧要么另写一套、要么放弃快路径，且新鲜性门禁可能随下沉而散失。
- **选项**：(a) 执行器整体下沉 mem-core；索引侧"构造即证明"——唯一构造函数 open_proved（stat 咨询 ∧ 只读打开 ∧ 只读 schema 门禁含 bad_records ∧ epoch 同代核对）产出实现 FindPrefilter trait 的已证明句柄，两前端经同一函数组装注入；(b) 双实现 + 一致性对账测试（MCP 侧独立实现，测试断言两端输出相等）；(c) MCP 经子进程转发调 CLI `mem find`。
- **后果**：(a) 破坏了会怎么表现——既有 CLI 代码要搬家，搬移期间 fastpath 等测试面需跟随调整（一次性工程成本）；此后改检索语义或快路径门禁必须动单源处（这本就是意图）；"构造失败即 None"的形状使半个证明的句柄无法被造出来，漏做门禁在类型上不可表达。(b) 破坏了会怎么表现——MCP 侧任何一处独立偏差都只能靠测试发现：本仓库 r7–r11 五轮评审反复复现"两套匹配实现必然漂移"（LF 假命中、NFC/NFD 不一致、大小写 ID 前缀），最后靠谓词单源化（r12 B7-1）才止血；再开第二套执行器等于把已消灭的漂移面请回来。(c) 破坏了会怎么表现——每次检索多一次进程拉起与 JSON→文本→JSON 往返，错误码与超时语义两头翻译；Windows 进程开销肉眼可见。
- **可逆性**：纯内部结构重组，随时可退；对外行为除"MCP list 可能改走快路径"（命中面等价，read_mode 标注差异）外无变更。
- **依据强度**：已验证——r7–r11 漂移复现与 r12 B7-1 单源化止住（search.rs 模块注释存证）；MCP list 恒直读（protocol.rs:158-173 核验）；crate 依赖方向（mem → mem-mcp；mem-mcp 已依赖 mem-index，Cargo.toml:13 核验）；现有快路径含 epoch 代际核对与只读 schema 校验（commands/mod.rs:301-315、sqlite.rs:105-137 核验）——构造函数承接的是既有门禁的全集，不是新发明。未验证——构造即证明形状在当前 crate 图上的工程成本（估计小，未实施）。
- **推荐 + 默认**：(a)。默认 (a)。
- 下钻：search.rs 模块注释（r12 B7-1）；D5（索引约束仅对账诊断）；红线8/18/21；评审报告 B3。

### 决策③ 可过滤字段声明词汇：属性级 `x-filter: true`

- **背景**：需求已裁决过滤由类型声明驱动（基础设施按声明解释执行、对具体类型零知识），但"哪些字段可过滤、取值形态"用什么词汇声明是需求阶段留下的未收口项，归设计与既有自定义关键字同批评审。
- **选项**：(a) 属性级 `x-filter: true`（位置在 `properties.<字段>` 内，与 x-ref 同位）；(b) 根级清单 `x-filterable: [字段…]`；(c) 独立过滤声明文件（types/<t>/filters.json）。
- **后果**：(a) 破坏了会怎么表现——想一眼看全"本类型哪些字段可过滤"要通读 properties（约定文档可弥补；schema 本身可读性略降）。(b) 破坏了会怎么表现——字段改名要改两处（properties 与清单）；漏改或打错时，过滤调用报"字段未声明"而 schema 看上去完好——声明与定义之间出现双源漂移。(c) 破坏了会怎么表现——两件套变三件套，交付面与加载面加宽（R8.8 例外化）；仅为一个布尔标记引入整份文件过重。
- **可逆性**：词汇新增是增量——回退 = 删声明行 + 词汇表降版；已发布声明在旧机制上被当注记忽略（前向兼容已核验）。
- **依据强度**：已验证——x-ref 属性级先例（type-declaration.md §1.1 位置列）；未知 x-* 被校验器当注记（keywords.rs 行为核验）；取值形态由属性 schema 本体承载 = 单源（不重复声明 type/enum）。未验证——第二个真实类型的过滤需求形态（起源场景仅教材库一型）。
- **推荐 + 默认**：(a)。默认 (a)；v1 支持形态固定四类（string/number/boolean/标量数组），超出者 verify 告警。
- 下钻：R10.10；提案决策⑤未收口项；D19/红线13 同族先例（词汇属基础设施、类型仍纯数据）。

### 决策④ 过滤等值语义：规范条件 = 字段＋标量文本 + 兼容类型集逐类型解释

- **背景**：载荷字段过滤的需求未定义四件事——"值相等"的语义（大小写形式不同算不算等）、跨类型查询时未声明该字段类型的行为、**多个类型声明同一字段但取值形态不同**时谁说了算、以及过滤条件的**输入形态**（CLI 是文本、MCP 是 JSON，若 JSON 类型参与语义选择，会产生只有一端能表达的命中集）。四处留白都会造成"同一查询两种都合规的实现"或两端不可对账，须一并钉死。
- **选项**：(a) **规范过滤条件 = 字段＋标量文本**：CLI 值原样为文本、MCP filters 值一律 JSON 字符串（非字符串标量显式拒收）；每个声明该字段的类型按自身声明解释同一文本（string 折叠等值、number 按 JSON 数值文法解析后数值等值、boolean 认 `true`/`false`）；候选类型集检查（全未声明→错误；未声明与不兼容类型静默不命中）；兼容集为空→错误；精筛按每条记录自身类型的声明裁定等值；(b) 两端显式类型语法（如 `--filter status:string=1` / MCP 类型化包装对象）——可表达"只要某一形态"的子集，但同一字段多形态的合并条件在两端都不可表达（过滤只有合取、重复字段显式错误），且两端各加一层语法面；(c) 字符串精确等值＋候选集内同名声明必须同形，否则整个请求报错。
- **后果**：(a) 破坏了会怎么表现——想按大小写区分两个仅大小写不同的值（"AI"与"ai"作为不同板块）时办不到——与身份键折叠同型的既有让步；异形同名时一次过滤是"各类型按自身声明解释同一文本"的合并命中（A∪B），只要其中一端形态的子集须经 `mem list --type` 收窄；MCP 直接传 JSON 数字/布尔被显式拒收（想传 1 得传 "1"）。(b) 破坏了会怎么表现——"各形态合并"的查询（不关心字段在哪个类型里是什么形态，都要）在两个前端都发不出来；两端语法面各翻一倍，文法教学成本上升。(c) 破坏了会怎么表现——换着大小写输过滤值（"geometry" vs "Geometry"）得到零命中，用户无法区分"没有该值"与"大小写打错"；两个类型恰好都有 status 但形态不同（一个字符串枚举、一个数字）时，对 status 的一切过滤被拒——尽管各类型内部语义清清楚楚，类型作者还背上跨类型协调字段形态的新义务。
- **可逆性**：等值语义与输入规范形态是对外行为——收紧或放宽都改变命中集与错误面，须评审。
- **依据强度**：已验证——折叠单源（paths.rs:40）已被检索/索引/别名解析三面共用；数值等值按 JSON 数值语义确定（"1" 与 "1.0" 同值，文本形态陷阱消除）；规范条件 = 文本使两端合法条件空间逐字相同——"每个合法过滤语义在两端都可表达"结构性成立，无需逐案对账；合并与子集表达在两端各有同径入口（find/untyped list 给合并，`--type` 收窄给子集）。未验证——大小写敏感过滤的真实需求（无声索）；同名字段异形在真实类型集中的出现频率（无数据）。
- **推荐 + 默认**：(a)。默认 (a)。
- 下钻：R10.4（折叠等价的精神同源）；R8.4 注记（按声明解释执行）；评审报告 r1 B2 / r2 B4。

### 决策⑤ 过滤参数形状：CLI `--filter 字段=值` 可重复；MCP `filters` JSON 对象

- **背景**：过滤条件如何进入两个前端是对外接口面，须一次定形；前端功能对等原则要求新增能力同批落两端。
- **选项**：(a) CLI 可重复长参 `--filter k=v`（合取）＋ MCP JSON 对象 `{"k": v}`；(b) CLI 单参逗号串 `--filter k=v,k2=v2`；(c) CLI 定位参数式（`mem find 板块=几何 绝对值` 混入位置参数）。
- **后果**：(a) 破坏了会怎么表现——值含空格时需引号包裹（shell 常规）；重复同字段得显式错误而非静默后写覆盖。(b) 破坏了会怎么表现——值含逗号时要转义——为过滤再造一套转义语法，且与查询词项文法叠加后用户要同时记两套规则。(c) 破坏了会怎么表现——位置参数与查询词项混排，解析两可（`板块=几何` 是词项还是条件？），与 find 的 query 单参数形状冲突。
- **可逆性**：接口面——发布后改名/改形属行为变更须评审。
- **依据强度**：已验证——CLI 既有可重复长参先例（--trail）；MCP 既有对象参数先例（mem_add payload）。未验证——无。
- **推荐 + 默认**：(a)。默认 (a)；值以第一个 `=` 分界（值可含 `=`）；空值显式错误。
- 下钻：R10.10；R10.1。

### 决策⑥ mem_find 工具形状：新工具 + mem_list 增 filters；find 不收空查询

- **背景**：MCP 侧检索工具的命名与参数形状归设计（提案 §5 不裁决清单）；CLI 已有独立 find 子命令，对等原则要求工具协议有对应工具。
- **选项**：(a) 新增 mem_find（query 必填）＋ mem_list 增 filters；(b) mem_list 增可选 query 参数合一（不新增工具）；(c) mem_find 收空 query（纯过滤也走 find）。
- **后果**：(a) 破坏了会怎么表现——宿主工具数 +1（15 个）；"纯过滤不带关键词"须调 mem_list——多记一个入口。(b) 破坏了会怎么表现——一个工具两副语义（清单/检索），参数校验与文档面翻倍；CLI 有独立 find 而工具协议没有对应物，对等原则在工具面上失语。(c) 破坏了会怎么表现——find 的 query 从必填变可选，"检索"与"过滤清单"两个语义挤一个入口，与 (b) 同病。
- **可逆性**：新工具是增量——回退 = 下架（已依赖它的宿主受影响）；mem_list.filters 同。
- **依据强度**：已验证——CLI 23 子命令中 find 独立存在；MCP tools/list 动态可见（新工具无需宿主升级协议）。未验证——宿主对工具数量的实际敏感度（无数据）。
- **推荐 + 默认**：(a)。默认 (a)。
- 下钻：R10.1；提案范围 1/4。

### 决策⑦ 坏记录告警承接：全量收集 + 上限 200 + verify 续读；indexed 经 bad_records 表

- **背景**：需求（v1.4 修订口径）把完备召回限定于可判定记录，并要求坏记录以独立告警暴露位置、不可判定原因与修复入口。现状 find/list 响应不带任何告警（仅校验例程可见），索引快路径更是根本不经过扫描。
- **选项**：(a) 扫描/物化期全量收集，find/list 响应透出（上限 200、截断标注、verify 续读）；(b) 查询相关化（仅"身份前缀似命中"的坏记录才报）；(c) 只在 direct 路径透出（indexed 不透）。
- **后果**：(a) 破坏了会怎么表现——坏记录多且与查询无关时，每次 find/list 都带一串无关告警（受 200 上限约束），清单变啰嗦。(b) 破坏了会怎么表现——"似命中"只能以文件名启发式判定：id 在 frontmatter 里，坏记录恰恰读不出 id；无唯一键类型文件名是 id、有键类型是 slug——同一坏记录一型报一型不报，用户问"为什么"没有一致答案；启发式自身成为新的漂移面。(c) 破坏了会怎么表现——sidecar 在场（快路径）时告警反而消失——告警可见性随部署形态漂移，验收 10 在最常见的集成档上不成立。
- **可逆性**：响应增量字段——回退 = 删字段（依赖告警的调用方受影响）；bad_records 表随索引重建消失，无格式迁移。
- **依据强度**：已验证——scan_all 已收集告警（ops.rs:59-80 核验）；物化与扫描共用同一扫描源（表可同源填充）；新鲜性证明保证两路径告警集合一致。未验证——真实库中坏记录的常见数量（无数据；200 上限兜底）。
- **推荐 + 默认**：(a)。默认 (a)。
- 下钻：R10.3 与验收 10（v1.4 B3）；R6.2；红线9/18。

## 8. 实施顺序建议（验收真源在 §4，此处只排先后）

## 10. 术语与锚点

| 术语/锚点 | 含义 |
|---|---|
| 词项 | 查询中空白分隔的检索单元，按逐域谓词匹配；可带否定标记（R10.8/R10.9） |
| 否定标记 | 词项前缀半角 `-`（U+002D），全角连字符不是标记；匹配串 = 去标记后的原串 |
| 折叠 | 大小写与等价字符形式归一（NFC + Unicode 小写映射）；单源 `crates/mem-core/src/paths.rs::fold`，检索/过滤/索引三面共用 |
| 粗筛/精筛 | 索引 SQL 近似条件取超集候选（只多不漏）／回读记录文件后由命中谓词单源精确判定——语义由精筛裁定 |
| 快路径/直读 | 索引新鲜性可证明（检查点 ∧ 订阅覆盖）时走索引／否则全量直读真相层并标注 read_mode=direct |
| 命中序号分页 | offset 语义 = 命中序列中的序号（非扫描偏移），续读不重不漏 |
