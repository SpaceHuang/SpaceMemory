# SpaceMemory MCP 安装引导方案（Codex + Claude Code）

- 状态：方案经 r2 复审通过；TDD 实施完成，macOS 隔离 CLI 验收通过；Windows 验证尚未完成。
- 日期：2026-11-12。
- 范围：通过 `mem` 命令，将本机已安装的 SpaceMemory 注册为 Codex 或 Claude Code 可启动的 MCP 服务；客户端类型未指定时，提供不绑定具体 Agent 的通用 MCP stdio 启动参数，由当前 Agent 自行判断接入方式。

## 评审结论与决策边界

复审报告 `docs/review/mcp-agent-installation-design-review-r2.md` 已批准首版命令形状、Codex / Claude Code 用户级安装、未指定客户端时的通用引导，以及同名配置处理方式。本方案只覆盖安装入口，不更改 MCP 工具定义、记忆数据格式、记录数据目录或发布渠道。

### 决策 1：用什么方式注册 MCP

**背景**：SpaceMemory 已能通过 `mem mcp` 以标准输入输出方式运行 MCP 服务；Codex 和 Claude Code 都需要在各自配置中登记启动命令，才能发现工具。

| 选项 | 用户结果 | 选错时的表现 |
|---|---|---|
| A. 调用目标客户端自己的 MCP 命令写入配置（推荐） | 使用 `codex mcp add` 或 `claude mcp add`；客户端负责维护自己的 TOML/JSON 配置格式。 | 客户端 CLI 未安装时，自动登记无法完成；SpaceMemory 输出可复制的安装命令和配置示例，用户仍可手动完成。 |
| B. SpaceMemory 直接编辑两个客户端的配置文件 | 不需要客户端 CLI，也可从 `mem` 直接写入。 | 客户端改变配置格式或路径后，SpaceMemory 可能破坏已有设置；还要自行处理注释、并发编辑、备用配置目录和版本差异。 |

**推荐与默认**：选 A。安装前只读取目标用户范围的配置文件来检查同名项，不运行会连接已有 MCP 服务的列表/健康检查命令；新增配置仍由客户端 CLI 写入。配置路径无法确定、文件无法读取或解析失败时停止，不做写入，并输出通用引导。客户端 CLI 不存在或执行失败时也不报告安装成功。

**可逆性**：可使用客户端自带的 `mcp remove` 删除注册。注册只新增 MCP 启动入口，不安装/卸载客户端本身。

**依据强度**：本机隔离实验确认 Codex `mcp list --json` 可读取登记，但 `codex mcp add` 会覆盖同名项；Claude Code `mcp list` 会启动已有服务进行健康检查，因此不得用于安装前预检。官方 CLI 添加命令仅用于实际登记。客户端版本变化时若配置路径或格式无法安全识别，必须停止并转手动引导。

**下钻**：[Codex MCP 配置文档](https://developers.openai.com/codex/mcp/)；[Claude Code MCP 配置文档](https://docs.anthropic.com/en/docs/claude-code/mcp)。

### 决策 2：首版安装到哪个范围

**背景**：Codex 有用户级与项目级配置；Claude Code 有用户级、项目级和当前项目私有配置。范围决定哪些项目能调用 SpaceMemory，以及是否会把配置写入项目仓库。

| 选项 | 用户结果 | 选错时的表现 |
|---|---|---|
| A. 只安装到当前用户范围（推荐） | 该用户在 Codex 和 Claude Code 的项目中都可使用；配置留在用户自己的配置区，不进入仓库。更高优先级的项目配置仍可能覆盖它。 | 想只给单个项目使用的用户仍需手动改用项目级配置；首版不替他写项目文件。 |
| B. 提供用户级和项目级选择 | 团队可把项目级配置提交到仓库共享。 | 安装器要处理仓库路径、Claude Code 项目审批和配置提交边界；Agent 可能未经预期就改动仓库配置。 |

**推荐与默认**：选 A。对显式指定的 Codex 使用其默认用户配置；对显式指定的 Claude Code 明确传 `--scope user`。首版不提供 `--scope` 选项，避免在 Agent 工作目录和用户全局配置之间产生隐式选择。未指定客户端时只输出通用启动参数，不对安装范围作假设。

**可逆性**：客户端都提供按名称移除 MCP 的命令；转为项目级配置时，由用户在目标仓库手动操作。

**依据强度**：Codex 官方文档确认可使用 `~/.codex/config.toml`，也可使用项目级 `.codex/config.toml`；Claude Code 官方文档确认用户级服务保存在 `~/.claude.json`，可在用户所有项目中使用。项目级服务有额外审批和仓库共享行为。

**下钻**：[Codex MCP 配置文档](https://developers.openai.com/codex/mcp/)；[Claude Code MCP 范围说明](https://docs.anthropic.com/en/docs/claude-code/mcp#user-scope)。

### 决策 3：同名服务已存在时如何处理

**背景**：客户端配置中可能已有名为 `spacememory` 的服务，且可能指向不同版本或不同数据目录。

| 选项 | 用户结果 | 选错时的表现 |
|---|---|---|
| A. 安装前检查，确认空缺后继续（推荐） | 已有同名项就停止；未发现时调用客户端命令登记。少见情况下，另一程序可能恰好在检查后添加同名项。 | Codex 命令可能替换这条同时添加的配置；安装后只核对最终配置，无法识别被替换的内容。 |
| B. 没有条件创建能力时一律不自动写入 | 即使检查时没有同名项，也只输出手动步骤。 | 避开检查后的并发窗口，但常规安装也无法自动完成。 |

**推荐与默认**：选 A。只读检查目标用户配置；发现 `spacememory` 已存在时停止，未发现时继续调用客户端 CLI 添加，并在完成后只读核对结果。这个检查是尽力保护：它不能锁住客户端配置，无法阻止另一程序在检查后同时添加同名服务。考虑到这种同时修改并不常见，首版不增加风险开关；文档与结果提示如实说明这项边界。

**可逆性**：客户端的移除命令可显式清掉旧注册；再运行安装命令即可重新登记。

**依据强度**：Codex CLI 0.153.0 隔离实验确认 `codex mcp add` 会成功覆盖并替换同名设置；预检与安装器自有锁不能保护 Codex CLI、用户或其他不遵守该锁的写入者。尚无经验证的跨写入者条件创建接口。此方案接受少见并发窗口，不声称消除了它。

**下钻**：本轮评审报告 B2。

### 决策 4：怎样检查同名配置而不启动现有服务

**背景**：预检需要知道目标用户配置中是否已有 `spacememory`，但部分客户端的服务列表命令会启动已有 MCP 服务做健康检查。

| 选项 | 用户结果 | 选错时的表现 |
|---|---|---|
| A. 只读解析目标用户配置文件（推荐） | 不运行任何 MCP 服务；无法确定路径或解析内容时安全停止。 | 配置格式更新后解析器可能需要同步升级；遇到未知格式必须停止，不能猜测。 |
| B. 调用客户端服务列表/健康检查命令 | 使用客户端提供的服务列表。 | Claude Code 会启动已配置服务，导致安装预检运行用户未要求启动的程序。 |

**推荐与默认**：选 A。Codex 只读解析 `$CODEX_HOME/config.toml`（未设置时 `~/.codex/config.toml`）中的用户级 `mcp_servers.spacememory`；Claude Code 只读解析其当前用户 MCP 配置 JSON（默认 `~/.claude.json`，设置 `CLAUDE_CONFIG_DIR` 时按该环境的实际用户配置根解析）。实施前必须用隔离配置目录和真实 CLI 验证路径映射。不得在预检、重名退出或写后验证中运行 `claude mcp list`、`claude mcp get` 等会启动现有服务的命令。目标文件缺失表示目标范围当前无登记；文件无法读取、JSON/TOML 解析失败、路径解析不明或结构未知时停止且不写入。

本首版只查目标用户范围，不扫描项目、工作区、组织管理或其他配置源。若项目级服务遮蔽了用户级 `spacememory`，安装器不改项目配置；结果说明该项目可能继续使用其更高优先级定义。此检查结论只描述目标用户配置文件，不宣称当前所有项目的有效服务集合。

**可逆性**：该步骤只读。客户端 CLI 添加完成后，通过同一只读解析器确认用户配置中的目标项；用户可主动使用客户端命令查看实时连接状态，但该动作须由用户或 Agent 单独发起。

**依据强度**：本地评审实验确认 `claude mcp list` 会启动服务；官方文档确认 Claude Code MCP 配置在 `~/.claude.json`，Codex 使用 TOML 用户配置。`CLAUDE_CONFIG_DIR` 下 MCP 文件的精确映射列为实施前置验证；若无法确定，自动安装停止并输出通用引导。

### 决策 5：找不到客户端 CLI 时要怎样引导

**背景**：有些用户可能只安装了 Codex 桌面应用，或 Claude Code 的可执行文件不在 `PATH` 中。

| 选项 | 用户结果 | 选错时的表现 |
|---|---|---|
| A. 打印手动安装命令和对应配置片段，不尝试自行写文件（推荐） | 用户可安装/定位客户端 CLI 后执行，或手动复制配置；原配置不受影响。 | 用户需要再执行一步，不能在本次命令中自动注册。 |
| B. 由 SpaceMemory 直接编辑默认配置文件作为后备 | 不需要客户端 CLI 也能自动写入默认配置路径。 | 自定义配置目录或客户端格式变更会让服务写错位置，甚至破坏原配置。 |

**推荐与默认**：选 A。错误输出必须包含绝对的 `mem` 可执行文件路径、可复制命令、对应客户端的验证命令，并说明重新启动/载入客户端的方式。不得只说“找不到命令”。

### 决策 6：用户没有指定 Agent 时，输出什么安装引导

**背景**：用户可能使用首版没有专用安装器的其他 Agent。MCP 规定服务如何与宿主通信，但不规定各 Agent 的配置文件、字段名、安装命令或重载步骤。

| 选项 | 用户结果 | 选错时的表现 |
|---|---|---|
| A. 只输出通用 stdio 启动参数，让当前 Agent 按自身方式配置（推荐） | Agent 可根据当前宿主选择正确入口；引导不会把其他 Agent 错当成 Codex 或 Claude Code。 | Agent 若不支持本机 stdio，无法自动接入；它应说明限制并向用户询问下一步。 |
| B. 默认输出 Codex 或 Claude Code 的配置细节 | 对这两个宿主更短。 | 使用其他 Agent 的用户会找不到配置位置，或误改另一个客户端的设置。 |

**推荐与默认**：选 A。不给配置文件范例或客户端命令，只给 MCP 服务名称、stdio 传输、本机命令绝对路径和参数数组；明确这是一组启动参数，不是所有客户端通用的配置文件。要求 Agent 先识别宿主，再按该宿主的说明配置；无法识别或不支持 stdio 时先向用户说明，不得猜客户端。

**可逆性**：通用引导不修改任何配置；Agent 完成配置后，用户按当前宿主的方式管理或移除服务。

**依据强度**：MCP stdio 是协议通信方式；配置文件、安装范围、命令行语法和重载方式属于宿主应用实现，不存在能直接用于所有 Agent 的统一配置文件格式。其他 Agent 的 stdio 支持情况未逐一验证。

## 用户能看到的命令

首版提供以下入口：

```text
mem --help
mem mcp --help
mem mcp install
mem mcp install --client
mem mcp install --client codex
mem mcp install --client claude-code
mem mcp install --client codex --dry-run
mem mcp install --client claude-code --dry-run
mem mcp
```

- `mem --help` 在命令清单中列出 `mcp`，并给一行简短提示：`mem mcp --help` 查看安装引导。
- `mem mcp --help` 以普通语言说明：MCP 是让 Agent 调用 SpaceMemory 工具的连接；安装的是本机 MCP 服务入口；默认使用 `$MEM_STORE` 或 `~/.agent-memory`；安装不会初始化店或改动记录；最后给出通用 stdio 参数和 Codex / Claude Code 专用安装命令。
- **`mem mcp install` 未提供客户端类型时不报错，也不尝试猜客户端或改配置**：`mem mcp install` 与 `mem mcp install --client` 都输出一段可复制给当前 Agent 的通用引导文字，并以成功状态退出。引导只提供通用 stdio 启动参数，要求 Agent 判断自身宿主并按其方式配置；无法确认宿主或 stdio 支持时，应先询问用户，不得假设为 Codex 或 Claude Code。
- `mem mcp install --client <client>` 执行客户端专用登记流程。客户端名首版只接受 `codex` 和 `claude-code`；未知值应报错并列出支持值。
- 预检发现目标用户配置中已有同名服务时停止；未发现时继续调用客户端 CLI。预检不能阻止检查后另一程序同时添加同名服务；若发生，客户端命令可能替换它。安装后只读核对最终配置，不增加风险开关。
- `--dry-run` 只检查当前 `mem` 路径和客户端 CLI，展示将执行的参数及配置范围，不写配置，不启动长期服务，不触碰记忆数据目录。
- `mem mcp`（没有后续管理子命令）保持现有行为：进入 stdio MCP 请求循环，供宿主启动。此行为必须与安装管理命令明确分流，避免把 `install` 当作协议输入。

## 安装行为

### 不带客户端时输出给 Agent 的通用引导

`mem mcp install` 和 `mem mcp install --client` 都直接打印下面这段可复制文本。不要输出任何客户端专用配置路径或命令。路径以 JSON 字符串字面量形式输出，保证反斜杠、引号、空格和非 ASCII 字符可还原；不能输出需要 shell 转义的路径：

```text
请帮我把本机的 SpaceMemory 接入当前 Agent，按以下步骤完成并验证：

1. 先识别当前 Agent 宿主及其本机 MCP 配置方式；不要假定是 Codex 或 Claude Code，也不要只凭项目目录猜。
2. SpaceMemory MCP 服务启动信息：服务名称 `spacememory`；传输方式 `stdio`；启动命令（JSON 字符串字面量）是 `{MEM_EXECUTABLE_JSON}`；参数数组 `["mcp"]`；不要求额外环境变量或特定工作目录。解码后才是实际可执行路径。这里描述的是通用启动参数，不是所有 Agent 共用的配置文件格式。
3. 查阅当前宿主的说明或设置界面，确认它支持本机 stdio MCP 后，使用该宿主自己的安装命令、配置文件或设置界面登记服务。先检查目标范围是否已有同名配置；发现已有同名服务时停止，说明现状和处理选项，不自动覆盖。若同时修改配置的风险与当前操作相关，告知用户检查后无法防止另一程序同时添加同名服务。
4. 安装后用当前 Agent 提供的状态页或命令确认服务已连接，并检查 SpaceMemory 工具列表可见。若当前会话不能热加载，告诉我如何重启或开启新会话。
5. 如果无法识别宿主、宿主不支持本机 stdio 或安装失败，先告诉我原因及需要的信息；不要猜测其他 Agent 的安装命令或修改配置。

安装只添加 Agent 的本机服务启动配置。它不会创建记忆店；服务之后会以当前用户身份运行，并可能调用 SpaceMemory 的读写工具。
```

生成该文本本身不得启动客户端命令，不得改客户端配置，不得启动 MCP 服务，也不得访问默认记忆目录。只有用户或 Agent 后续明确选定宿主并采取其配置步骤时，才进入客户端配置流程。

### 共同规则

1. 解析并规范化当前运行的 `mem` 可执行文件路径。传给 CLI 的路径通过进程参数数组传递，不做 shell 拼接；通用引导中的路径使用 JSON 字符串编码。若路径不能无损表示为客户端配置支持的 Unicode 字符串，停止自动安装并提示用户移动/重装到可表示的路径。
2. 配置文件示例/片段必须用对应格式序列化生成；不得把 shell 引号规则复用为 TOML/JSON 转义规则。解析生成的配置，确认解码后的命令路径与实际可执行文件路径逐字节/逐 UTF-16 单元一致。
3. MCP 名称固定为 `spacememory`，服务启动参数固定为 `mcp`。
4. 只登记客户端启动命令，不运行 `mem init`、`mem_session_start` 或 `mem reconcile`，也不创建记忆店。实际工具运行时仍由服务按现有默认链读取店路径。
5. 预检只能使用决策 4 定义的目标用户配置文件只读解析；严禁为了列出服务而运行会启动服务的命令。目标配置缺失时可继续；读取/解析失败、配置根不明、结构未知或同名存在时停止。
6. 客户端 CLI 添加成功后，再只读解析同一配置文件确认写入。只有配置中能读回本次期望的命令与参数，才报告“已登记”。若命令失败或回读不符，显示原因并给手动步骤；不得运行健康检查命令替代验证。
7. Codex `add` 的同名并发窗口按决策 3 处理：检查时发现同名就停止；检查时为空则继续添加。成功提示说明预检不能阻止另一程序在检查后同时添加同名服务，最终配置可能覆盖该并发添加。
8. 如需验证 MCP 协议自身，可启动 SpaceMemory 二进制并发送 initialize / tools/list，不调用任何记忆读写工具。客户端连接健康检查只作为用户主动操作说明，不能由安装器自动运行。
9. 输出完成后说明客户端可能要重启或开新会话，才能加载新增服务；安装命令本身不重启其他应用。

### Codex

预检与写后确认都只读解析 `$CODEX_HOME/config.toml`（未设置时 `~/.codex/config.toml`）中的 `mcp_servers.spacememory`，不调用 `codex mcp list`。若已存在同名项则停止；未发现时调用 `add`。Codex `add` 可能覆盖预检后由另一程序同时登记的同名项；此并发窗口不设开关，安装结果应说明这一限制。

逻辑调用为：

```text
codex mcp add spacememory -- <绝对路径>/mem mcp
```

此处表示程序 `codex` 和独立 argv 项；实现不得把整行当 shell 字符串执行。

预检发现同名时不调用以上命令；预检为空时通过进程 API 传递参数，不经过 shell。写后由安装器只读解析 TOML 并核对配置。检查后若另一程序同时添加同名项，Codex 命令可能替换它。官方文档也支持在 `~/.codex/config.toml` 直接配置 stdio 服务。用户可自行执行以下命令查看已配置服务；安装器不得依赖它确认写入：

```text
codex mcp list
```

Codex TUI 可用 `/mcp` 查看活动服务；Codex 桌面应用若未刷新，提示用户重启应用后再检查。手动 TOML 示例：

```toml
[mcp_servers.spacememory]
command = "/absolute/path/to/mem"
args = ["mcp"]
```

若输出可复制命令或 TOML 片段，须按目标 shell/TOML 编码；配置示例由 TOML 序列化器生成，不能直接拼接路径。

### Claude Code

预检和写后确认只读解析当前用户 MCP JSON 配置；不得调用 `claude mcp list` 或 `claude mcp get`。默认配置在 `~/.claude.json`；设置 `CLAUDE_CONFIG_DIR` 时，首版必须先用隔离目录验证客户端实际读写文件路径，路径无法确定时停止并转为通用引导。仅检查用户范围；项目/本地范围的同名配置可能遮蔽用户范围条目，安装器不修改这些文件。

逻辑调用为：

```text
claude mcp add --transport stdio --scope user spacememory -- <绝对路径>/mem mcp
```

此处表示程序 `claude` 和独立 argv 项；实现不得把整行当 shell 字符串执行。

`--` 之后的路径和参数属于 MCP 服务启动命令。`--scope user` 使服务对该用户的 Claude Code 项目可用，避免因安装时的当前目录不同而只写进某一个项目。预检发现同名时停止，未发现时按客户端 CLI 行为添加；安装前用真实客户端确认该行为，写后用只读解析器确认用户配置，不启动健康检查。若检查后另一程序同时添加同名项，客户端行为可能导致该项被替换；首版不提供风险开关。用户可自行选择运行以下命令查看实时连接，但这会启动已配置服务进行健康检查：

```text
claude mcp list
```

Claude Code 交互会话可用 `/mcp` 查看服务状态；如果当前会话没有更新，提示用户开新会话。手动 JSON 示例：

```json
{
  "mcpServers": {
    "spacememory": {
      "type": "stdio",
      "command": "/absolute/path/to/mem",
      "args": ["mcp"]
    }
  }
}
```

用户级配置的标准位置为 `~/.claude.json`；正常安装优先调用 Claude Code 自己的 CLI，而不是直接编辑该文件。

## 安装结果与权限说明

只有登记成功时，安装结果才报告“已登记”；预检发现同名或检查失败而停止时，必须明确说明配置没有被修改。成功提示必须表达以下事实：

- Codex 或 Claude Code 获得了启动本机 `mem mcp` 进程的配置；Agent 可发现并调用 SpaceMemory MCP 发布的工具，包括会改动记忆数据的工具。
- MCP 进程以当前用户身份运行，使用 SpaceMemory 现有数据目录选择规则；登记本身不读写记录，也不新建记忆店。
- 具体工具调用由 Agent 宿主发起；需要写入时仍执行 SpaceMemory 现有令牌校验和业务约束。
- 安装不代表客户端已在当前窗口完成重载。用户可按输出的检查命令确认配置，再按客户端提示重启应用或新开会话。Claude Code 的连接健康检查会启动已配置服务，因此只作为用户主动操作，不由安装器运行。
- 同名检查发生在客户端 CLI 写入之前，不能阻止另一程序在检查后同时添加同名服务；这种少见情况下，客户端 CLI 可能替换并发添加的配置。

## 实施边界与验收

首版新增面只有：CLI 的 MCP 帮助/安装命令，以及对 Codex、Claude Code 用户范围的 MCP 注册。不得顺带新增 HTTP 服务、云端服务、项目仓库配置、MCP 工具、权限绕过、记忆目录初始化或自动卸载。

实现时按 TDD 先写测试，至少覆盖：

1. `mem --help` 列出 MCP 引导，`mem mcp --help` 显示两个客户端及说明；`mem mcp` 仍进入原 stdio 服务。
2. `mem mcp install` 与缺少值的 `mem mcp install --client` 都输出完整、JSON 字符串路径可还原、可复制给 Agent 的通用引导文字；不得包含假定 Codex / Claude Code 的命令或配置路径。这两种调用不调用客户端 CLI，不改配置，不碰记忆店，且返回成功状态。
3. 只接受两个客户端名，错误帮助会列出有效值。
4. 两个客户端收到的命令名、参数、用户范围和 `mem` 绝对路径正确；命令经进程参数数组传递，不经过 shell。配置字符串由 TOML/JSON 序列化器生成并能往返还原；测试路径含空格、反斜杠、单引号和非 ASCII 字符。
5. dry-run 不写配置、不触发安装命令、不创建店目录。
6. 用会写启动标记的现有 MCP 服务证明安装预检、同名停止、读取/解析失败路径均不启动它。若客户端列表命令用于用户主动验证，文档要明确是否会启动已有服务。
7. 客户端命令不存在、启动失败、返回非零、预检配置不可读/格式错误或服务重名时均不误报成功；预检时目标配置文件缺失允许继续，客户端命令成功后配置仍缺失或回读不符则不报告成功；错误路径不运行健康检查命令。
8. Codex 并发交错测试覆盖“预检为空→另一写入者登记同名→本次安装继续”，确认这一少见交错可能覆盖并发写入，并确保实现、成功提示和文档都如实说明这一边界；不测试或提供风险开关。
9. Claude Code 的 `CLAUDE_CONFIG_DIR` 路径映射与同名添加语义用隔离配置目录和真实 CLI 验证；不确定时自动安装 fail closed。
10. 客户端命令成功后通过纯配置回读确认登记，并输出重载指引；安装器的 stdio 探针完成 initialize 与 tools/list，不调用工具。
11. 在 macOS 与 Windows 运行自动化测试；用真实 Codex CLI 与 Claude Code CLI 各做一次外部验收，记录配置路径、客户端版本与结果。Claude 真实健康检查由用户主动执行，不作为安装步骤。

## 自曝三处

1. **并发覆盖**：Codex `add` 没有条件创建保证。首版按用户决定不增加风险开关：只在预检发现同名时停止，预检为空则继续。另一程序若恰好在检查后登记同名服务，Codex 仍可能替换它；安装提示和验收须明确这一限制。
2. **配置作用域与路径**：首版只读写用户级目标配置，不扫描更高优先级或项目配置；Codex 项目配置可能覆盖用户配置。Claude 的 `CLAUDE_CONFIG_DIR` MCP 文件位置须用真实 CLI 实验确认，无法确认时安全停止。
3. **宿主副作用与路径文本**：Claude `mcp list` 会启动已有服务，不能由安装器运行；所有路径展示、进程参数及 TOML/JSON 片段使用各自编码方式，不能用一套引号规则代替。
4. **工具访问权限**：安装后 Agent 不仅能读，还能调用写工具。最终帮助与成功输出必须明确本地进程权限、记忆目录和写工具事实。

## 对本轮评审的响应

- **B1 关闭方向**：不运行 `claude mcp list` / `get` 做预检或写后验证；只读解析精确的用户级 JSON 配置。目标路径不明或文件格式异常时停止。实时连接健康检查由用户主动运行。
- **B2 按用户决定处理**：不增加并发风险开关。预检发现同名就停止；预检为空则继续调用客户端 CLI，并在帮助/结果说明中提示：检查后另一程序若同时添加同名服务，客户端命令可能替换它。该方案不提供并发保护，接受该少见窗口。
- **C1 关闭方向**：只检查正在安装的用户范围，不把 Codex/Claude 的其他配置层合并成“无同名”；提示项目级配置可能遮蔽用户级条目。自定义 Claude 配置目录用隔离 CLI 确认，否则停止自动安装。
- **C2 关闭方向**：通用提示中的可执行路径是 JSON 字符串字面量；客户端 CLI 通过 argv 调用；TOML/JSON 片段分别序列化并做往返校验。Shell 可复制命令必须标明适用 shell。
